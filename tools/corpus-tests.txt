# The corpus gate's inventory: every #[ignore]d test in the workspace.
#
# `tools/corpus-gate.sh --verify-list` (which CI runs) fails when this file and
# cargo disagree in either direction — a test that quietly stops being in the
# gate, and a gate that names a test nobody wrote, are the same bug seen from
# two ends. Adding an ignored test means adding a line here, on purpose.
#
# A test belongs here when it reads something outside the repository: the
# measurement target, its doc-gen4 tree, a generated IR tree, or one of the
# `--full` recordings. See docs/plans/quality-gates.md 決定 1.
#
# The name is `<cargo test target>::<test>`, because three different tests are
# called `the_corpus_matches_the_prototype` and two are called `the_whole_corpus`.
# A trailing `# …` says what the test needs.

## frozen — no regenerator in HEAD; the generator is at tag `experiments-frozen`
#
# `crates/lean-doc-render/tests/data/PROVENANCE.md` states it plainly: "There is
# no regenerator in this tree any more." Everything below needs something only
# the removed prototype could write, so running it can only ever panic. They stay
# in the inventory — they are real tests and they will run again if somebody
# restores the generator — but the gate does not attempt them, because a
# permanently red gate is one nobody reads.
#
# **Two kinds, and the second was only recognised on 2026-08-16**:
#
#   1. `--full` recordings the prototype's renderer made (5.6 / 29 / 77 MB).
#   2. **Trees the prototype wrote, which `/private/tmp` has since emptied** —
#      `m1/ref-pages` (its 432 rendered pages) and `w7h/base-state` (its state
#      file). The **directories are still there and empty**, so these four read
#      as "no input" rather than as a disagreement about bytes; the committed
#      fixtures they compare against are fine. Regenerating the input needs the
#      renderer at the tag, which is what puts them here.
#
# Not here on purpose: `docgen4::the_whole_corpus` and `md4lean::the_whole_corpus`
# also want a `--full` recording, but **their oracle is doc-gen4 / MD4Lean itself
# and both generators are in HEAD**, so the input is a `deno run` away and they
# belong above.
