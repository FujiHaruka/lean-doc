# lean-doc UI 刷新 — M8

**位置づけ**: [`../implementation-plan.md`](../implementation-plan.md) が**実装の SoT**。この文書はその
**M8 の詳細** — doc-gen4 の HTML / CSS / JS を模倣するのをやめ、**IR はそのままで UI を自前にする**段の、
技術前提・段の順序・ゲート。結果は [`../milestone-log.md`](../milestone-log.md) に落とす。
数字には CLAUDE.md「計測の誠実性」の 4 ラベル (実測 / 外挿 / 仮定 / 理論値) を付ける。
**作成**: 2026-08-16。

**ゴール**: `lean-doc build` が出した木を**そのまま置けば動くサイト**にする。
いまは置いても見た目が付かない (静的資産を 1 本も生成しない) し、入口 (`index.html`) も無い。

## 2. Context — 何が既にあり、何が無いか

### 2.1 変えないもの

M1〜M7 で作った**データの層**は 1 バイトも変えない:

- IR (schema 4) の読み書き、台帳、鍵
- autolink の名前解決 / `.lidx` / `ExternalLinks` (M7 の版固定 blob URL)
- UTF-16 の扱い (implementation-plan.md §7 の U1 / U2)
- md4c の FFI と docstring → HTML
- 増分 (detect / ownership / merge / impact / prune)
- **何をページに出すか** — `Suppressed`、`page_items` の順序、members / equations / instances の有無

変えるのは **HTML のタグと class、CSS、JS** だけ。

### 2.2 いま空いている穴【すべて実測 2026-08-16】

| 穴 | 実体 |
|---|---|
| **静的資産を 1 本も生成しない** | `style.css` / JS 6 本 / `favicon.svg` は `<head>` から参照だけされて出力されない (`frame.rs:61-124`)。`include_str!` の全 18 ヒットはテスト fixture |
| **入口が無い** | `index.html` / `404.html` / `search.html` / `foundational_types.html` を生成しない。ページはこの 4 本を href に持つ (`frame.rs:157`, `code.rs:209`) |
| **`declaration-data.bmp` の形式ズレ** | doc-gen4 の JS が読む `instancesFor` が無く、`modules[].url` も無い → 公開サイトの Instances For (**245 ページ**) と Imported By (**432 ページ**) が壊れている |
| **CDN 依存 4 本** | `style.css` が Lato と JuliaMono を `@import`、`<head>` が polyfill と MathJax を読む |
| **iframe ナビ** | `<nav class="nav"><iframe src="navbar.html">`。navbar.html は **57,949 B** のフラットな `<li>` 列で、doc-gen4 の `nav.js` が期待する `<details data-path>` を出さないので **nav.js は何もしない** |

### 2.3 いま公開されているもの【実測 2026-08-16】

`https://fujiharuka.github.io/information-theory/` (gh-pages ブランチ `8b1f5b0`、**手動 push**、
`build_type: legacy`、`custom_404: true`)。中身は **lean-doc が出した 438 ファイル + doc-gen4 の
静的資産 17 本を手でコピーしたもの**。`search.html` は**コピーし忘れていて 404** —
ページ右上の Search ボタンの飛び先がこれ。**デプロイのワークフローもスクリプトも存在しない。**

## 3. Approach

> **IR も「何を出すか」も変えない。「どう出すか」だけを全部自前にする。**
> 段は「資産を出せるようにする → ページの形 → 動き → 入口 → 再ホスト」の順で、
> **各段の終わりに実ブラウザで見る**。

**なぜこの順か。** 資産を出す土台 (M8-a) が無いと、CSS を書いても**どこにも置けない**ので
見た目を確認できない。逆に土台さえあれば、以降の各段は「資産を差し替えるだけ」で効果が見える。
**HTML と CSS は必ず同じコミットで動かす** — 片方だけ進めると、どちらが壊したのかが
実ブラウザでしか分からない状態が続く。

**先にプロトタイプを書く。** CSS を Rust の文字列リテラルの中で試行錯誤するのは最悪なので、
**手書きの静的 HTML で見た目を固めてから**、同じ構造を Rust に落とす。プロトタイプは
`design/preview/` に置き、**CSS と JS の実体は最初から製品の置き場所** (`crates/lean-doc-render/assets/`)
に置いて、プロトタイプがそれを相対パスで参照する — **資産を 2 箇所に持たない**ため。

**やらないこと**: IR の拡張。「この情報があれば良い UI になる」と気づいても、M8 では
**既に IR にあるものだけ**で作る。IR を変えると抽出器・台帳・増分の全部が動く。

## 4. 技術前提 — 決定と、根拠になった実測

### 決定 1 — CSS フレームワークは使わない。自前で書く

| 候補 | 却下理由 |
|---|---|
| **Tailwind** | **ビルドチェーンが要る。この環境の npm / node は壊れている** (JS は deno)。加えてユーティリティクラスは 432 ページの HTML 側に載るので、共有 CSS 1 本より**総バイトが増える** |
| **Bootstrap / Bulma** | クラス前提 + JS 依存。API ドキュメントに要らないものが大半 |
| **Pico.css / Simple.css** (classless) | 効くのは reset と typography だけ。**このサイトの中身の大半は宣言ブロック**で、それは自前で書くしかない。トークン体系が二重になる |

**採るもの**: 最小リセット + 設計トークン (CSS custom properties) + コンポーネント層の 3 層を自前で書く。
**目標は 1 ファイル 15 KB 未満**【目標値。実測は M8-b で】。
参考: doc-gen4 の `style.css` は **18,677 B / 836 行**【実測】。

**この決定が守っているもの**: **依存ゼロ**。site 木は `lean-doc build` の出力だけで完結し、
ネットワークもツールチェーンも要らない。CDN が死んでもサイトは死なない。
**サイズは理由ではない** — 自前のほうが大きくなったとしても、この決定は変わらない。

### 決定 2 — Web フォントを読まない。システムの等幅フォントに任せる

対象パッケージの本文には**非 ASCII が 178 種**出る【実測 2026-08-16。348 ページからタグを落として集計】:

| 頻度上位 | α 13,057 / ₁ 8,329 / ₂ 8,058 / β 7,706 / → 6,784 / μ 6,351 / Ω 6,111 / ℝ 5,454 / ℕ 3,600 / ≤ 3,378 |
|---|---|

doc-gen4 が **JuliaMono を CDN から読む理由がこれ** — 添字 (₁ ᵢ ᵐ ⁿ) と double-struck (ℝ ℕ ℤ) を
持つ等幅フォントは多くない。それでも読まない判断をするのは、**CDN を 1 本残すと決定 1 が崩れる**から。
代わりに等幅スタックに**数学記号を持つフォントを並べる**
(`ui-monospace` / `SF Mono` / `Menlo` / `Consolas` / `DejaVu Sans Mono` / `Liberation Mono`)。

**この決定が仮定していたこと**: 上のスタックで 178 種が**読める字形にフォールバックする**。
**字幅は崩れうる** (プロポーショナルなフォールバックが混ざる)。

**決着【実測 2026-08-17】— 仮定は成立。UI-V1 は発火しない。**
ブラウザゲートの検査 8 が 178 種を実際に描いて測る (`benchmarks/tools/mono-charset.json`、
生成は同ディレクトリの `mono-charset.py`)。**2 OS とも字形の欠け 0**:

| | 字形の欠け | 等幅の送り幅と違う字 | 実際に描いたフォント (Chrome の `CSS.getPlatformFontsForNode`) |
|---|---|---|---|
| macOS 26.0 | **0 / 178** | 34 | `Menlo:140` / `Apple Symbols:20` / `STIX Two Math:7` / `.SF NS:4` / `Osaka:7` |
| CI `ubuntu-latest` | **0 / 178** | 22 | `DejaVu Sans Mono:157` / `DejaVu Sans:13` / `DejaVu Math TeX Gyre:7` / `Liberation Mono:1` |

**等幅スタック単独では覆えていない**、というのがこの表の本体 — どちらの OS でも
**等幅フォントは 178 種の 8〜9 割**しか描いておらず、残りは記号フォントや**プロポーショナル**の
フォールバックが埋めている。だから**字幅が崩れるのは仕様どおり起きている** (22〜34 種) が、
この決定はそれを最初から受け入れているので**判定には使わない**。読めない字が出たら落ちる。

**まだ測っていないのは Windows** (`Consolas`)。機材がここに無い。

**否定されたら** → **UI-V1**: JuliaMono (SIL OFL、再配布可) を**この 178 種 + ASCII にサブセットして
vendor する**。サブセット化には fonttools が要る (**この環境には未導入**【実測】)。

### 決定 3 — 数式は「あるページだけ」で読む

対象 348 ページのうち **TeX の数式があるのは 1 ページ**、`$` の出現は **12 個**【実測 2026-08-16】。
全ページに MathJax (CDN、1 MB 級) を読ませるのは 347 ページで無駄。
→ **レンダラが docstring に数式マーカーを見つけたページにだけ**数式の経路を出す。

**v0.1 では数式エンジンを vendor しない**【判断】 — 1 ページのために数百 KB を木に入れるほうが歪む。
`$$…$$` は**そのままの文字列として読める**ので、壊れるのではなく**組版されないだけ**。
→ **UI-V2** (第 2 の対象で数式が多かったらこの判断は変わる)。

### 決定 4 — iframe ナビを廃止し、モジュールツリーは JSON から描く

`navbar.html` は **57,949 B**【実測】。432 ページに埋め込むと **約 25 MB 増える**ので埋め込みは却下。
iframe は残せるが、**モバイルでスクロールが親と噛み合わず、現在位置の同期に JS が要り、
doc-gen4 の `expand-nav.js` はそのためだけに存在している**【実測】。
→ **ツリーは 1 本の JSON として出し、ページ側は JS で描く。** 1 度取れば `sessionStorage` に載る。

**この決定が捨てるもの**: `file://` で開いたときのツリー — `fetch` が同一オリジンで止まる。
配布先は GitHub Pages (HTTP) なので v0.1 では許容する。**書いておくのは、これが「気づかなかった」
ではなく「捨てた」だからで、`lean-doc serve` を作る日に戻ってくる。**
JS を切っても本文は読めるようにし、`<noscript>` にモジュール一覧 (`index.html`) へのリンクを置く。

### 決定 5 — 検索はクライアントで、索引は専用に出す

doc-gen4 の `search.js` は `declaration-data.bmp` (**lean-doc 版で 1,216,017 B**【実測】) を
**毎回まるごと fetch して線形走査する** (IndexedDB キャッシュは doc-gen4 側で無効化されている【実測】)。
検索に要るのは (名前, kind, リンク) の 3 列だけなので、**それだけの索引を別に出す**。
**4,750 宣言**【実測】で数百 KB、gzip 後はその 1/5〜1/6【外挿。GitHub Pages は gzip を掛ける】。

### 決定 6 — 静的資産は Rust バイナリに埋め込む

`crates/lean-doc-render/assets/` に実体を置き、`include_str!` でバイナリに入れて、
`lean-doc build` が site 木へ書き出す。**理由**: インストールが `cargo install` 1 本で済み、
**資産の版とレンダラの版が構造的にずれない** — CSS が参照する class 名を変えたのに古い CSS が
配られる、という壊れ方が起きない。

**帰結**: 資産は **`renderKey` に入れない**【決定】。CSS / JS が変わっても**ページのバイトは変わらない**ので、
鍵に混ぜると 432 ページの再レンダリングを誘発するだけで何も得しない。代わりに
**毎ビルド無条件に書き出す** (冪等、3 ファイル)。**増分が資産を孤児として消さない**ことが
**M8-a のゲート**。

## 5. 段とゲート

| | やること | ゲート |
|---|---|---|
| **M8-a** | 静的資産を site 木へ書き出す土台 (決定 6) | 空ディレクトリに `lean-doc build` して、**`<head>` が参照する資産が全部そこにある**。**増分でも消えず、古くもならない** |

## 6. 持ち込んではいけないもの

- **IR を変えない。** 抽出器・台帳・増分が全部動く
- **`experiments/` を変えない**
- **byte 互換を「ついでに」壊さない** — 壊すのは **M8-b の 1 コミット**で、そこで
  **落ちたテストを全部数えて記録する**。あちこちで少しずつ壊すと、どれが意図した変更かが分からなくなる
- **CDN を 1 本も足さない。** 「これだけは CDN で」は決定 1 の否定
- **見た目のために IR に無い情報を捏造しない** (例: 宣言の「説明文」を型から作る)
- **`declaration-data.bmp` の形式ズレを黙って直さない** — doc-gen4 の JS を捨てるので
  `instancesFor` / `modules[].url` の**要否そのものが変わる**。何を出して何をやめたかを M8-d に書く
- **プロトタイプと製品で CSS を 2 本持たない**

## 8. M8-d — 出すものと、やめるもの

**doc-gen4 の JS のためだけに存在していた成果物は、読み手ごと消える。** 残す判断の基準は
「**UI 以外に読み手がいるか**」の 1 点で、見た目の都合ではない。

| | いま | M8 後 | なぜ |
|---|---|---|---|
| `declarations/declaration-data.bmp` | **1,216,017 B**【実測】 | **やめる** | 読み手は doc-gen4 の 6 本の JS だけで、それを捨てる。**しかも現状すでに壊れている** — `instancesFor` が無く `modules[].url` も無いので、公開サイトの Instances For (245 ページ) と Imported By (432 ページ) が動いていない【実測】 |
| `declarations/name-map.json` | **602,729 B**【実測】 | **残す** | **増分パイプラインが `--before` で読む**。UI とは無関係で、消すと M3 の delta が死ぬ |
| `navbar.html` | **57,949 B**【実測】 | **やめる** | iframe ナビ専用。doc-gen4 の `nav.js` が期待する `<details data-path>` すら出しておらず、**いまも何も動いていない**【実測】 |
| `tactics.html` | カウント 2 つ入りの一文 | **やめる** | 対象パッケージの tactic docstring は **432 モジュールで 0 件**【実測】 |

| **`404.html`** | 無い | **作る** | GitHub Pages が `custom_404: true`【実測】 |

**UI-V5 は決着した。`instancesFor` は作れる — ただし仮説の規則ではない**【実測 2026-08-16】。

| | |
|---|---|
