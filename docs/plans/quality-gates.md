# 品質ゲート整備 — doc-gen4 を失った後の「緑」の定義

**位置づけ**: [`../implementation-plan.md`](../implementation-plan.md) が**実装の SoT**、この文書は
**その §1「緑の定義は `cargo test --workspace` が通ること」を実際に成立させる段**の計画。
結果は [`../milestone-log.md`](../milestone-log.md) に落とす。数字には CLAUDE.md「計測の誠実性」の
4 ラベル (実測 / 外挿 / 仮定 / 理論値) を付ける。**着手 2026-08-16**。

---

## 1. ゴールと完了条件

**ゲート A (doc-gen4 との byte 再現) は終了した** (実装計画 §1)。**消えたのは外部オラクルであって
テストの網ではない** — だがオラクルを失った以上、「何をもって緑とするか」を置き直さないと、
残った 355 本のテストは**自分が何を守っているか言えなくなる**。

| ゲート | 完了条件 | 判定 |
|---|---|---|
| **Q-A: 緑の機械化** | **機材ゼロ依存**で `cargo test --workspace` + clippy + fmt が通り、**それを CI が push ごとに判定する** | GitHub Actions が緑 |
| **Q-B: オラクルの代替** | 自己整合性・不変量・Lean 自身 の 3 種が実装され、**それぞれ母数付きの数字**が出る | 各ゲートのログ |
| **Q-C: e2e** | **抽出器 (Lean) から site まで**を本物で通す経路が CI にあり、生成物を**実ブラウザ**が開く | E1 / E3 が CI で緑 |

**やらないこと**: doc-gen4 互換ゲートの再建 (実装計画 §1 で「再定義しない」と決定済)。
**カバレッジ率を目標にしない** (「全件バイト一致は分岐被覆の証明ではない」→ milestone-log M1 と
同じ理由で、率は網の強さを表さない)。

## 2. Context — 何が既にあり、何が無いか【すべて実測 2026-08-16】

| | 事実 |
|---|---|
| テスト | **355 本 / 2 failed**。赤 2 件は `packages::every_root_matches_doc_gen4s_own_blob_urls` と `ledger::the_corpus_matches_the_prototype` |
| その赤の原因 | **lean-doc 側ではない** — 計測対象が `lakefile.toml` → `lakefile.lean`、依存 15 → 9 に動いた (milestone-log M8)。**テストを弱めない**と決定済 |
| corpus 依存 | 4 ファイル (`packages.rs` / `ledger.rs` / `pages.rs` / `base_ir.rs`)。**すべて既に skip 機構を持つ** — 対象が無ければ `eprintln!("skipping: …")` して緑 |
| CI | `.github/workflows/` は **4 本とも計測用** (importModules / prefetch / residency)。**`cargo test` を回すワークフローが 1 本も無い** |
| サイト検査 | `benchmarks/tools/check-dead-links.py` (UI-2 のゲート、**オフライン・オラクル不要**) と `check-site-links.py` (M7-c、**doc-gen4 の木がオラクル**) が**ある**。どちらも benchmarks 側 = 数字を取る道具で、ゲートとして回っていない |
| 抽出器との契約 | `build.rs` / `incremental.rs` の抽出器は `/bin/sh` の fake。**抽出器が吐く IR の形が変わっても cargo test は全部緑** |
| UI-3 | 「**未判定。実ブラウザで描画を見ていない**」と計画自身が書いている (ui-redesign.md) |
| `tools/build-gate.sh` | 冒頭が「**M7-c で参照側が古いので site diff は expected、失敗ではない**」と自ら書いている = **判定能力を失っている** |
| M4-a ゲート | 凍結バイナリ 1.7 GB 削除で**再現不能** (handoff) |

**「skip して緑」は正しい設計だが、半分しか正しくない** — CI では corpus が常に無いので**常に skip**
される。すると **CI の緑は corpus テストについて何も言っていない**のに、その事実がどこにも出ない。
**静かな skip は静かな過少レンダリングと同じ形の失敗**で、このプロジェクトは後者を型で塞いだ
(実装計画 §5「空集合と未指定を型で区別する」) のに、前者はまだ開いている。

## 3. Approach

> **オラクルを再建しない。オラクルが要らない判定を 3 種類置き、
> 「機材を要するか」でテストとゲートを分け、その境界を CI の境界に一致させる。**

doc-gen4 を失って消えたのは**外部オラクル** — 「正しい出力を知っている第三者」。
代わりに置けるものは 3 つしかなく、どれも外部を要らない:

| | 何を問うか | 例 |
|---|---|---|
| **(1) 自己整合性** | 出力は**自分の中で閉じているか** | 内部リンク 404 = 0、索引の宣言が実ページにある |
| **(2) 不変量** | **別経路が同じ答えを出すか** | 増分 == フル、決定性、`--jobs` 不変、順序不変 |
| **(3) Lean 自身** | 上流が**事実**を持っているか | 抽出した宣言集合 == 環境の宣言集合 |

**(2) が本命**。このプロジェクトは既に最強の不変量を 1 本持っている (「増分 == フル生成」)
のに、同じ強さのものを他に持っていない。**不変量はオラクルより強い場合がある** —
オラクルは「参照と同じか」しか言わないが、不変量は**参照が無い領域でも**破れを名指しする。

**第 2 の柱は「テスト」と「ゲート」の区別**。この語彙は既にツリーの中にある —
`resident.rs` が「それは Lean toolchain と 3 GB のプロセスが要るので、**ゲートであってテストではない**」
と書いている。**この線を CI の境界と一致させる**:

- **テスト** = 機材ゼロ依存。`cargo test --workspace` で緑。**CI が押す**
- **ゲート** = 機材・対象・toolchain を要する。`tools/*-gate.sh`。**人が押す (一部は CI が nightly で)**

**corpus 依存の 4 本は「テスト」ではなく「ゲート」だった** — 対象リポジトリが動けば壊れるものは、
定義上テストではない (テストは自分の入力を持つ)。skip 機構はその性質を**隠す**方向に働いていた。
**移すのが正しい。弱めるのではない。**

**やらないこと**: 既存テストの書き換え。**ゲートを足すのであって、網を張り替えるのではない。**

## 4. この計画で決めること

- **決定 1 — corpus 依存は `cargo test` から外し、`tools/corpus-gate.sh` に集める。**
  弱めない・消さない・skip も残さない。**`#[ignore]` を付け、ゲートが `--ignored` で名指しで走らせる。**
  理由: skip は「走らなかった」を stderr に流すだけで**終了コードに出ない**。`#[ignore]` なら
  `cargo test` の結果行が `N ignored` と**数を持って**報告する。
  **赤 2 件はこの移動で緑にならない** — ゲート側で赤のまま残り、母数の取り直し待ちであることが
  ゲートの出力に出る。**「CI が緑」と「対象に対する主張」を混ぜないための分離**であって、赤を隠す変更ではない
- **決定 2 — CI は 3 ジョブに分ける**: `test` (機材ゼロ) / `e2e-micro` (Lean toolchain、Mathlib 無し) /
  `browser` (headless Chrome)。**Mathlib を要するものは CI に載せない** (第 2 の対象は手動ゲートのまま)
- **決定 3 — 自己整合性ゲートは Python のまま**。実装計画 §2 の
  「**採点器を同じ言語・同じ設計で書くと両方同じ間違いをする経路ができる**」がそのまま効く。
  `check-dead-links.py` は既にオフラインでオラクル不要なので、**昇格させるだけで足りる**
- **決定 4 — 性能は壁時計でゲートしない。仕事量のカウンタでゲートする。**
  壁時計は page cache で 5 倍動く【実測、CLAUDE.md】ので CI では判定に使えない。
  代わりに**決定的な整数**を出す: IR 全読み回数 / 再抽出モジュール数 / レンダリングページ数 /
  抽出器プロセス起動回数。**「無変更なら 0 ページ」は既にこの形**で、一般化するだけ
- **決定 5 — fuzz はゲートにするが、時間ではなく corpus で回す。**
  CI で「N 秒回して落ちなければ緑」は非決定的。**コミット済みの seed corpus を全部通す**形にし、
  探索は手元で回して**新しい入力が見つかったら corpus に足す**。crash が出たら回帰テストへ落とす

### Q8 の検査 8 — 持っていた Linux 機材を使っていなかった【実測 2026-08-17】

`ui-redesign.md` 決定 2 は Web フォントを捨て、**システムの等幅スタックが対象の非 ASCII 178 種を
読める字形で出す**ことに賭けた。**その賭けは macOS でしか見ていない**と 1 日書き続けていたが、
**CI ランナーは `ubuntu-latest`** で、Linux の機材はずっとタダで手に入っていた。

検査 8 が足したもの:

- **文字集合はサイトからではなく対象から取る** (`mono-charset.json`、178 種)。e2e フィクスチャは
  意図的に小さいので、**そこに出る文字だけで判定すると `ℝ` を描けないスタックが通ってしまう**
- **判定は「字形があるか」だけ** — canvas に描いてインクが乗るかを見る。**送り幅は数えて報告するが
  落とさない**。決定 2 が「**字幅は崩れうる**」と明言しているので、落とすのは決定の書き換えになる
- **診断は Chrome の `CSS.getPlatformFontsForNode`** — 実際に描いたフォント名と字数が出るので、
  落ちたときに「どのフォントに何が無いか」が 1 行で言える。幅の数字では言えない

結果は 2 OS とも**欠け 0**。同時に**等幅スタック単独では 8〜9 割しか描いていない**ことも出た
(→ 決定 2 の表)。**ゲートを一度落として**から通した — 描画されない文字 (U+200B) を集合に混ぜると
`BROWSER GATE: 1 failed` になる【実測】。

### Q6 — 探索を回して分かったのは「何を検査していないか」だった【すべて実測 2026-08-17】

**`cargo-fuzz` の `-Zsanitizer=address` は Rust にしか届かない。**
`RUSTFLAGS` は Rust のコンパイルにしか渡らないので、**`build.rs` が `cc` で焼く md4c の C は
計装されない** — libFuzzer はパーサの中からのフィードバックを一切もらえず、ASan も
そこのメモリアクセスを見ない。**この状態で「100 万回回して落ちなかった」と書けてしまう。**
実際に見えていた差 (同じ seed corpus / `-seed=1` / `-runs=20000`):

| md4c | libFuzzer の `cov:` |
|---|---|
| 未計装 (`RUSTFLAGS` だけ) | **1023** |
| 計装 (`CFLAGS` に `-fsanitize=address -fsanitize=fuzzer-no-link`) | **2487** |

**これは §6 の「ゲートは走った本数を数える」と同型**で、今度は本数ではなく**被計装範囲**。
どちらも**出力は「合っている」ように見える**。捕まえたのは、
**計装したときとしないときで数字が動くかを見た**ことだけ。

ゲート側 (`fuzz_corpus.rs`) の負検査も取り直した: **`#[test]` の中で SIGSEGV を起こすと
`cargo test` は `exit=101`** で赤くなる【実測】。crash がテスト失敗として出ないなら
この corpus 全通しは何も主張していないので、そこを先に確かめた。

**探索は `fuzz/` に置いた** (`cargo-fuzz`、nightly、ワークスペース外)。**ゲートは安定版のまま**
— 決定 5 のとおり「時間で回す」ものを CI に入れない。**crash が出たら corpus に足す**という
一方向だけが CI に繋がっている。

**LeakSanitizer は macOS で走らない**ので、md4c が確保して解放しないバッファはここに出ない。

### Q5 が訂正させたもの — 数えたら docs が 3 つ間違っていた【すべて実測 2026-08-16】

**カウンタは「速度の回帰を見る道具」として作ったが、最初に出したのは自分たちの誤りだった。**

| docs の主張 | 実測 | 直した場所 |
|---|---|---|
| 「残る IR 全読みは **5 回**」(approach.md §5.6) | **シナリオ 1 つの値**。回数は**ラウンド数で動く** — 無変更 **1 回** / 1 ラウンド **約 4 回** / 2 ラウンド **約 5 回** / フル生成 **2 回**。「5 回」は L3-1 の 2 ラウンド | approach.md §5.6 に表を追加 |
| 「**IR へのアクセスを 1 つの抽象に集約する**」(実装計画 §3)、「every read of the IR is in this crate」(`reader.rs`) | **`index.json` を `lean_doc_ir` の外で読む経路が 3 つ** (`merge` / `extract_key` / `prune`)。**モジュールファイルについては真、index については偽** | 実装計画 §3 と `reader.rs` の見出し |
| — (誰も書いていなかった) | **`pages_rendered` が既に「2 つ目の真実」だった** — 再生成集合の要素数で報告していて、**レンダラが実際に書いたページ数ではなかった**。集合が IR に無いモジュールを名指すと食い違う | `pipeline::Summary` |

**`ownership` は 1 パスより高い (N+1 読み)** — 差分側が再抽出モジュールの新旧 2 本を読むため。
**`contentHash` キャッシュで消せるのは走査の側だけ**なので、
**V2 の取り分を「5 回 → 1 回」と見積もるのは楽観**【実測】。

→ **計測する道具を作ると、最初に見つかるのは計測対象ではなく自分の記述**という形になった。
CLAUDE.md「予測と結果が食い違ったら結果が SoT」をそのまま適用して計画側を直してある。

**Q2 の「順序不変」は取り下げた【判断 2026-08-16】** — 不変量ではなかった。
実装計画 §6 が記録しているとおり **`index.json` の `modules` 配列は「渡されたモジュール一覧の順」**
(M3-d2b) なので、順序を変えれば**バイトが変わるのが仕様**。
「不変量が破れた」ではなく「不変量ではないものを不変量と呼んでいた」ので、**実装しない。**
モジュール一覧を作る側 (`lean-doc modules` の glob) が決定的であることは、
**決定性ゲート (GATE 3) が既に覆っている** — 2 回のフル生成がバイト一致する以上、
一覧の順序も 2 回とも同じ。

**Q7 の判断 — サイズ予算は静的資産だけに置く。**
site 木も `.lidx` もモジュール数に比例するので、上限は対象が変われば意味を失う。
**`style.css` / `app.js` / `favicon.svg` だけが対象に依存しない製品の一部**で、
ui-redesign.md 決定 1 (「大きくなったら削る。フレームワークには戻らない」) が直接効く。
**上限は現在値ではなく丸い上の値に置く** — 現在値に貼り付けた予算は毎回落ちるので、
「中身を読まずに上限を上げる」習慣を教えてしまう。

**E2 (合成の第 2 の対象) は既存 `tools/target2-gate.sh` のまま**。Mathlib が要るので CI に載せない
(決定 2)。**`tools/build-gate.sh` は Q4 の後に畳むか作り直す** — 期待値が「差分が出ること」に
反転したまま残っている (§2)。

### Q4 が初回で見つけたもの — レンダラの実欠陥【実測 2026-08-16】

**`inductive` と `class_inductive` の constructor が、ページに 1 つも描かれていなかった。**
`decl.rs` の分岐が body を空のまま返していて、search 索引には載っているので
**検索で選ぶとページ先頭に着地する**という壊れ方をしていた (M7 が「宣言アンカーの 1.24% が
ソフト失敗」と呼んだのと同じ形が、自分の出力の中にあった)。

**これが今まで見えなかった理由が、この計画の主張そのもの**:

| なぜ見えなかったか | |
|---|---|
| **byte 再現ゲート** | 原理的に無理。オラクル (doc-gen4 の参照木) は**対象パッケージのページ**で、その対象に inductive が 1 つも無い |
| **既存の 355 本** | 1 本も反応しない。curated case は**分岐に到達すること**を assert していたが、**到達した結果**は見ていなかった |
| **`page_parts.rs` の記録** | 「41 分岐のうち 9 つは実データで発火しない」と**書いてあった**。書いてあっても、出力を見る仕組みが無ければ欠陥は残る |

→ **「全件バイト一致は分岐被覆の証明ではない」(milestone-log M1) の一段強い形**:
**オラクルの入力に無い形は、何バイト一致しても見えない。**
修正と回帰テスト (`an_inductives_constructors_are_rendered_with_their_own_anchors`) は同じコミットに。
**フィクスチャは「対象が持たない形」を構成として持つ** — これが E1 の設計原理 (→ `e2e/README.md`)。

### Q10 が拾った 1 件 — 生き残った変異は「読むためだけのコード」だった【実測 2026-08-16】

`decl.rs` の 74 mutant のうち唯一生き残ったのは **`UnplaceableName` の `Display` を

(doc-gen4 は同じ地点で panic し、こちらは返す。理由は「誤った href は誤ったバイトであり、
黙って出る誤りは 1 ラウンドの調査を要する」)。**名前を言わないエラーはその 1 ラウンドを結局使う。**
テストを足して **74/74**。

**ワークスペース全体は 1,602 mutant で未実施** — 1 個約 3 秒なので約 80 分。
**ゲートにはしないので急がない** (V6 の実例: UnicodeBasic ⊆ V8 なので「和」と「V8 のみ」は

### `tools/build-gate.sh` の gate1-site を止めた【判断 2026-08-16】

**期待値が「差分が出ること」に反転したまま残っていた** — M7-c で依存リンクが版固定 blob URL に
移り、参照側 (`lean-doc site` を `--root` 無しで呼ぶ) は相対リンクのままなので、
**設計上必ず食い違う**。それを毎回 FAIL と表示しては「無視してよい」と注記していた。
**読者に無視させるゲートは、その後どの出力も読まれなくなる。**
→ **実行をやめ、理由と代替 (`tools/e2e-micro.sh` の GATE 1〜3) を出力に書く。**
このスクリプトの残り (IR 比較・モジュール一覧・2 回目の run・本物の移動・本物の削除) は
**いまも判定している**ので畳まない。

### 訂正 — gate1-site は「判定不能」ではなかった【実測 2026-08-16】

**`lean-doc site` は `--root` を取る。** 上の判断は「参照側は構造上 `build` と同じリンクを
書けない」という前提に立っていたが、**その前提が誤り**。参照を `--root <target>` 付きで作れば
`site` も M7-c の版固定 blob URL を書き、`tools/target2-gate.sh` の gate1-site は
**20 ファイルがバイト一致して PASS に戻った**【実測】。**止めるべきだったのは比較ではなく、
参照の作り方だった。**

残る差は `site` が静的資産 3 本 (`app.js` / `favicon.svg` / `style.css`) を書かないことだけ。
**3 本を名指しで外し、1 本でも無ければ失敗**にした — `diff --exclude` に渡す形にすると
4 本目の差を黙って飲む (§6「例外リストを持つ比較器を作らない」)。

**同じ実走で、より重い欠陥が出た。`compare` は `RESULT FAIL` を印字して 0 を返していた** —
つまり **gate1-site が FAIL したまま `target2-gate.sh all` は exit 0** で、
gate2 / gate4 のバイト比較も含め**このスクリプトの比較はすべて終了コードに出ていなかった**。
失敗を数えて非ゼロで終わるようにし、**故意に 1 バイト足して exit 1 を確認してから通した**
(§6「ゲートは自分では自分を検査しない」)。

> **`tools/build-gate.sh` も同型**である可能性が高い (同じ `compare`、同じ `--root` 無しの参照)。
> **未確認** — あちらは対象のクローンを要するので、この訂正はまだ target2 側にしか当たっていない。

## 6. 持ち込んではいけないもの

- **テストを弱めて緑にしない。** 赤 2 件は対象が動いた事実の報告であって、バグではなかった
  (milestone-log M8「テストを弱めない」)。**移動と修正を混ぜない**
  → **決着済 (2026-08-16)**: 片方は**母数を取り直して緑** (manifest 15 → 9)、
  もう片方は**比較そのものを削除**した — 撤去したプロトタイプが**昔の対象**に対して書いた
  バイトが相手で、**問う相手がもういない**から。**弱めたのでも、再凍結したのでもない**
  (再凍結はオラクルを自分の出力に差し替えることになる)。**測っていた 34 分岐は合成パッケージへ移し、
  対象を要らなくなった分 CI に載った**。→ milestone-log「赤 2 件の決着」
- **オラクルを Rust で書き直さない** (決定 3)。自己整合性ゲートも同じ
- **カバレッジ率・mutation スコアを目標にしない。** V6 の実例 — UnicodeBasic ⊆ V8 なので
  「和」と「V8 のみ」は**等価なプログラム**で、mutation では原理的に守れない【実測】
- **CI に Mathlib を持ち込まない。** 数 GB のダウンロードは無料枠の外
- **壁時計を CI のゲートにしない** (決定 4)
- **新しいゲートの数字にもラベルを付ける。** サイズ予算の初期値は**仮定**から始まる
- **既存の 355 本を書き換えない。** 足すのであって張り替えるのではない
- **ゲートは「走った本数」を数える**【2026-08-16 に 4 件目で学んだ】。「skip で緑を返さない」の
  一般形。**走らなかったことは終了コードに出ない** — skip でも、名前の取り違えでも、
  `--no-fail-fast` 忘れで赤の陰に隠れても、出力は「合っている」ように見える。
  **inventory の本数と、実際に結果を報告した本数を突き合わせる**のが唯一これを捕まえた
- **入力の同一性を「パス」で判定しない**【2026-08-16 に踏んだ】。`link_index_fixture` は
  「既定パスなら母数まで検査、他のファイルなら構造だけ」という設計で、**既定パスに別物を置いた
  瞬間に主張の強さが黙って変わった**。同一性を主張するなら**中身で判定する** (digest / 生成条件)
