残ったものを、**「変更量が小さいか」ではなく「主張がそれを決める場所に置かれているか」**
で畳む。

| **R2** | `docs/provenance.md` §8【未検証、2026-08-22 起票】 | NOTICE が「バイナリに入る MIT 単独クレート」を網羅していない |

## 2. Approach — 主張は、それを決めるものと同じ場所に置く

R1 は「432 モジュールの corpus が無いので測り直せない」問題**ではない**。
測り直せないのは pin のうち 2 つだけで、**残る 1 つは corpus を一切必要としない
HEAD の構造についての主張**であり、それが今 HEAD と食い違っている。

`state_and_delta.rs:1205-1213` は、書かれた state ファイルの 1 モジュールぶんのキー列を
**「prototype の 7 キー + `instancesFor` 1 個」**と主張する。C-2 が `ModuleFacts::refs` を
足したので HEAD では **9 キー**。この assert は偽で、**誰も気づかなかった**。

**なぜ気づけなかったか — ここが一般形**:
`ModuleFacts` の「prototype が持つ 7 キー」には**転写が 2 本ある**。

| | 形 | フィールド追加が起きたとき |
|---|---|---|
| `tests/global.rs::Facts` | **射影** — 7 キーだけを再直列化する | **見えない。壊れない** |
| `tests/state_and_delta.rs` の appended-key 列 | **差分** — 「7 キー + 手書きの追加リスト」 | **腐る。しかも凍結テストなので黙って腐る** |

CLAUDE.md 「**判断は 1 箇所に集める。同じ問いに答える経路が 2 本あると、片方だけ直る**」の
実例そのもの。実際に片方 (射影) だけが生き残った。

### 取る形

1. **prototype の 7 キーを 1 箇所で定義する。** `litedoc4-global` に `pub const` として置き、
   `ModuleFacts` のフィールド順に関する doc コメント (`facts.rs:46-51`) が主張していることを
   **機械が検査できる形にする**。転写 2 本はこれを参照する。
2. **構造の主張を、機材ゼロ依存のテストへ移す。** 「直列化したキー列は prototype の 7 キーで
   **始まる**」は `ModuleFacts` の値 1 つあれば決まり、corpus も prototype state も要らない。
   **これは `#[ignore]` にしない** — 今日から走り、以後どのフィールドが増えても自動で覆う。
   凍結テスト側は「7 キーで始まる」だけを言い、**その後に何が続くかは HEAD の話**として手放す。
   手書きの追加リストは消える。腐る場所そのものが無くなる。
3. **corpus × HEAD の同時性質である整数は、条件と一緒に置く。**
   `got.len() == 861_999` と `shim.len() == 841_947` は「HEAD がどうか」でも
   「corpus がどれか」でもなく**両者の積**で、裸の整数のままだと落ちたときに
   どちらが動いたのか 1 行で言えない (CLAUDE.md「落ちたときに何が壊れたか 1 行で言えない
   ゲートは足さない」)。**数字の SoT は `benchmarks/results/`** なので、テストには
   条件付きの主張として残し、`861_999` は復元者が測り直す対象であることを
   **assert の側から見える形**にする。
4. **オラクル本体 (`want == shim`) は触らない。** どの artifact も運ばない 818,331 B の
   facts に対する唯一のファイル型オラクルで、殺すと戻せない。frozen 分類のまま。

**この形を選ぶ理由は作業量ではない。** (a) corpus 復元は空きディスク 17 GB で
2026-08-17 の枯渇事故 (対象の olean 欠落) を再現しうるうえ、**復元しても
「差分の手書き」という腐り方は残る**。(b) byte 比較の廃止は腐り方を消すが、
オラクルも一緒に消す。**3 の形だけが、腐る構造そのものを消してオラクルを残す。**

### R2〜R5 に共通する形

R2 は `cargo deny` が**許可リストとの照合しかしない**ので抜けが緑で通る、という
「見ていないのに走っている」型 (CLAUDE.md「ゲートの被検査範囲を数字で確かめる」)。
R3〜R5 は「作れば測れる」。**どれも先に現況を確認してから着手する** —
CLAUDE.md「docs の『未』は腐る。項目を潰す前にまず現況を確認する」。

## 4. 撤退ライン

- **R1 の 3 で「凍結テストが走らないままなら検査していないのと同じ」なら、この計画は失敗**。
  そうならない根拠は、移した先の構造テストが**機材ゼロ依存で今日から走る**こと。
  移設して `cargo test --workspace` の本数が増えなかったら、移せていない。
- **R3〜R5 で「機材が無い」に着地したら、それは 2026-08-18 の
  「機材が無いのではなく持っている機材を使っていなかった」の再演を疑う。**
