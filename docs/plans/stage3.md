# 検証段階 3 — 依存パッケージの IR なしでリンクが解決できるか

**位置づけ**: [`three-axes.md`](three-axes.md) の leg 1〜3 の中身。
判断基準は `docs/approach.md` §7 の 3 行目。結果は `docs/verification-log.md` に書く。

**状態**: 未着手。

---

## 1. 問い

段階 1・2 で抽出フェーズは 11.82 秒 (実測) まで来た。ただしこれは
**自パッケージを閉じた世界として処理した値**で、署名は文字列に落としているだけ。
リンクは 1 本も張っていない。段階 3 が問うのは速度ではなく**成立性**:

> 依存パッケージ (Mathlib 8,169 モジュール) の IR を作らずに、
> 「宣言名 → モジュール → URL」の写像だけでリンクが張れるか。
> その写像は誰が、どれだけの大きさで持つのか。

ここが崩れると §6.4(b) の 2,400 倍 — プロジェクトの存在理由 — が崩れる。

**判断基準** (§7):
- (a) Mathlib へのリンクが正しく張れる — doc-gen4 が実際に出力した HTML と同じリンク先になる
- (b) 必要な写像の実サイズが分かる — 下限 (実際に参照される分) と上限 (依存全体) の両方

## 2. Approach

**doc-gen4 が既に答えを出しているのを使う。** 対象リポジトリには doc-gen4 の完成した
HTML 出力 (876 MB) と、検索用データ `declarations/declaration-data.bmp` (**37.5 MB**、実測)
がある。形式からして**求めている写像そのもの**:

```json
{"declarations":{"AEMeasurable":{"docLink":"./Mathlib/.../MeasureSpaceDef.html#AEMeasurable","kind":"def"}, ...}}
```

したがって段階 3 は写像を発明する話ではなく、**3 つの実測で挟む**話になる。

1. **需要側** — lean-doc が署名から参照する依存定数を列挙する → 写像の**下限**
2. **供給側** — その需要を `declaration-data.bmp` が満たすか照合する
   → §8「公開ドキュメントから導けるか」の答え。**上限は 37.5 MB**
3. **正しさ** — 生成したリンクを doc-gen4 の HTML の `<a href>` と突き合わせる
   (段階 2 で DB とやった手を、今度は HTML に対して)

速度の検証ではないので、**新しい時間の数字は 1 つだけ** (署名タグ付けの追加コスト。
段階 2 で `--tag` として +0.4 秒を実測済みなので、その再確認)。
**段階 3 の成果物はバイト数と一致率であって、秒ではない。**

## 3. 増分

新規に `experiments/stage3/` を足す (stage1/2 は触らない)。
stage2 の `Extract.lean` を起点にコピーして育てる。

### 増分 1 — 参照定数の列挙 (Lean 側)

stage2 は `format` した文字列しか持っていない。doc-gen4 の `tagCodeInfos` 相当を入れて、
`Format` のタグ (`Elab.Info`) から**署名中に現れる定数名**を回収する。

- 出力: 宣言ごとの参照定数リスト + 全体のユニーク集合 (JSONL)
- 出す数字 (すべて実測):
  - 参照定数のユニーク数、**自パッケージ / 依存側の内訳**
  - 1 宣言あたりの平均参照数
  - 追加コスト (段階 2 の `--tag` +0.4 秒と整合するか)
- **範囲を先に決める**: doc-gen4 は署名と equation をタグ付けし、docstring は別経路
  (`Output/DocString.lean`)。**初手は署名 + equation まで**とし、
  docstring 内のリンクは増分 3 で差分として測る。
- 落とし穴: タグは pp オプション `pp.tagAppFns` に依存する。段階 2 でここを取り違えて
  「9.5% 速く見えた」事故があるので、doc-gen4 と同じオプションで測る。

### 増分 2 — 写像の実サイズ (需要 ↔ 供給の照合)

増分 1 のユニーク集合を `declaration-data.bmp` に照合する。

- **カバレッジ**: 参照定数のうち bmp に存在する割合。**存在しないものを分類する**
  (自パッケージ由来 / blacklist されて実ページが無い / 内部名 / エイリアス)
- **サイズ**: 3 通りを実測して並べる

  | | 内容 |
  |---|---|
  | 全体 (上限) | `declaration-data.bmp` 37.5 MB (raw) / gzip 後 / ロード時間 |
  | 依存側のみ | 自パッケージの宣言を除いた分 |
  | 実際に参照される分 (下限) | 増分 1 のユニーク集合だけに絞った分 |

- **`kind` 列が要るか**を判定する。doc-gen4 はリンクの見た目を kind で変えている。
  要るなら写像は 2 列ではなく 3 列
- 出す数字: 件数・バイト数 (raw / gzip)・ロード時間 (環境ロードの床 2.5 秒と比べて何割か)

**ここが §8「写像をどう配布するか」の決着点。** 下限が上限より 2 桁小さいなら
「必要な分だけ引く」設計が成立し、同程度なら「37 MB を丸ごと持つ」しかない。
どちらでも設計は成立するが、**常駐・CI・配布の形が変わる。**

### 増分 3 — URL 生成と正しさの照合

- モジュール名 → URL の規則を実装
  (`Mathlib.Analysis.Asymptotics.Defs` → `.././Mathlib/Analysis/Asymptotics/Defs.html#<decl>`)。
  相対パスの起点は出力側の関心なので、**IR には絶対的な識別子 (モジュール名 + 宣言名) を持ち、
  相対化は出力時**にする — §5.6 の境界と一致させる
- **突き合わせ先**: `.lake/build/doc/InformationTheory/**.html` の `<a href>`。
  段階 2 の `compare-modules.py` と同じ位置づけのツールを
  `benchmarks/tools/compare-links.py` として足す
- 落とし穴: HTML のリンクは署名以外 (import 一覧・ナビ・docstring) にも出る。
  **宣言の署名ブロック内に限定して抽出しないと一致率が意味を持たない。**
  1 ファイル 146 リンクのうち何本が署名由来かを先に数える
- 出す数字: 一致率、不一致の**分類** (件数だけでなく原因ごと)

### 増分 4 — 判断

`docs/verification-log.md` に段階 3 の節を足し、`approach.md` §5.3 / §8 / §6.4(b) を
結果に合わせて直す (食い違ったら結果が SoT)。

## 4. 仮説が否定される条件 (撤退ライン)

- **依存側の blacklist が写像から復元できない** → 実ページの無い宣言にリンクしてしまう。
  「IR なしでリンクできる」が部分的に崩れ、依存側から取るべき情報が増える。
  → §5.3 を「写像 + 除外集合」に書き換える
- **参照定数の解決に環境が要る** (エイリアス・`@[reducible]` な別名の解決など)。
  段階 2 で `H(μ; X | Y)` が出なかったのと同種の問題が、リンク側で起きうる
- **写像のロード時間が環境ロードの床 (warm 2.5 秒) と同等以上**
  → 「外部参照は安い」が崩れ、写像自体の索引化が必要になる
- **公開ドキュメントに `declaration-data.bmp` 相当が存在しない / バージョン対応が取れない**
  → 「生成側で作る」しかなくなり §8 の答えが変わる (ただし成立性は崩れない)

## 5. 計測条件

段階 1・2 と同一に揃える。M1 / 8 コア / 16 GB、Lean・Mathlib・doc-gen4 すべて v4.31.0、
並列度 1、**warm** (壁時計 ≒ user+sys で確認)、連続 5 回以上。
時間を出すのは増分 1 のタグ付けコストだけだが、そこでも 1 回計測は使わない。
