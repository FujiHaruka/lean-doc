## 1. 棚卸しの結果 — 13 件がどう分かれたか【2026-08-18】

**測るのは 5 件**。残りは「未検証ではなかった」もの:

| 測る | なぜ |
|---|---|
| **U1** 依存 root 27 件の外部リンク | オフラインのオラクルが無いだけで、**HTTP なら確かめられる**。死にリンクは 2026-08-17 に実際に 10 本出た前科がある |
| **U2** 同名宣言 25 件のページ配置 | 「第 2 の対象で再現できない」で止まっていたが、**対象 1 に 25 件実在する**【実測 → verification-log §判明したこと 3】。フィクスチャを作る必要がない |
| **U3** Windows の等幅フォント / ダークの実際の色 | 下の Approach。**機材はある** |
| **U4** md4c のリーク検査 | 同上 |
| **U5** 新しい Lean で extractor が建つか | 「後方互換はやらない」という**決定**と混ざっていた。**前方追随は別物**で、利用者が最初に踏む |

**測らないと決めたもの** — 未検証ではなかった 4 件と、閉じた 2 件、保留 2 件:

| | 扱い |
|---|---|
| `--root` 無しの `ledger check` が違う `renderKey` を出す | **意図された挙動**。`build.rs` §"What `renderKey` covers" が「解決が劣化 → 別 digest → 全再描画」を明示的に選んでいる。誤りは出ない → **決定** (診断の 1 行を足すかは別件) |
| fenced code block 中の NUL | 「合わせる相手が無い」は照合の話。**出力に生 NUL を残すかは照合と無関係にこちらが決められる** → **仕様判断** |
| Lean の後方互換 | 「あらゆるバージョンへの後方互換は意図的にやらない」と既に決めている → **決定** (前方追随だけ U5 に残す) |
| スクリーンリーダー | 自動化できない (axe-core は代替であって SR ではない) → **持たないと決める** |
| プロトタイプとの乖離 3 件 | 照合相手を作るには doc-gen4 の出力が要る = **M8 で終了した決定に逆行** → **閉じる**。「オラクルを持たない」と書く |
| `lake exe cache get` のローカル未通過 | CI で実走済みで**経路は同一**。ローカルで通らないのは依存が既にあるから → **閉じる** |
| 他人のリポジトリから `uses:` される | 別リポジトリの作成が要る【ユーザー判断】 → **保留** |
| ギュメ付きモジュールを持つ「版固定できる依存」 / 大きいパッケージ・小 RAM ランナー | 作れる (git 木フィクスチャの機構は `bf4c6b6` にある) が条件が狭い / コストが高い → **保留** |

## 2. Approach

> **「機材が無い」と書いてある項目のうち 2 件は、機材が無いのではなく持っている機材を
> 使っていない。** 残り 3 件は手元で測れる。**新しい機材を要求する項目は 1 つも無い。**

`quality-gates.md` §Q8 が 2026-08-17 に記録した失敗と**同型**:

> その賭けは macOS でしか見ていないと 1 日書き続けていたが、**CI ランナーは `ubuntu-latest`** で、
> Linux の機材はずっとタダで手に入っていた。

今回そこに残っているのは 2 つ:

- **Windows** — 「`Consolas` を持つ機材がここに無い」は**手元**の話。全 CI が `ubuntu-latest` のみで、
  **`windows-latest` を一度も使っていない**。検査 8 (mono-charset 178 種を canvas に描いてインクを見る)
  は OS 非依存の作りなので、**ランナーを足すだけで判定が出る**
- **LeakSanitizer** — 「macOS で走らない」も**手元**の話。`ubuntu-latest` では走る。
  探索 (fuzz) を CI に乗せない決定 5 とは別で、**リーク検査は corpus 全通し 1 回で足りる**

**この 2 件は「未検証」ではなく「見ていなかった」に近い。** だから最初に潰すのではなく、
**安い順**に並べる — U1/U2 は手元で今日測れて、U3/U4 は CI を 1 往復する。

**各段は落ちうる形で書く。** CLAUDE.md「ゲートは自分では自分を検査しない」に従い、
**新しい検査は必ず一度落としてから通す**。特に U1 は「叩いていないのに緑」、
U3 は「文字集合が空でも緑」になりやすい形なので、**負検査を先に書く**。

## 3. 段と合否判定

| 段 | 何を測るか | 合格 | 落ちる形 |
|---|---|---|---|
| **U1** | 対象 1 のサイトが書いた外部 blob URL を root ごとに 1 本サンプルし、HTTP で実在を確かめる。**オラクルが届かない 27 root を全部通す** | 39 root すべてで 200 (行アンカーは URL の実在まで) | 404 が出る = 版固定リンクの組み立てが間違っている root がある |
| **U2** | 対象 1 の site で、同名宣言 25 件が**どのページに載り**、**索引からのリンクが解決するか** | 25 件すべてでリンク先ページに実体がある | 索引が指すページに宣言が無い = 検索で選ぶと着地に何も無い (M4 で出た壊れ方と同型) |
| **U3** | ブラウザゲートを **`windows-latest`** でも回す + **ダークの実際の色**を computed style で検査 | Windows で mono-charset 178 種の欠け 0、ダークで前景/背景のコントラスト比が閾値以上 | 字形が欠ける / ダークで読めない色 |
| **U4** | `ubuntu-latest` で **ASan + LSan** を corpus 全通しに当てる | leak 0 | md4c が確保して解放しないバッファが出る |
| **U5** | **v4.31.0 より新しい toolchain** で extractor が建つか。建つなら IR が取れるか | 建って IR が出る、**または大声で落ちる** | 黙って壊れた IR を書く (これが最悪) |

**U5 の合格に「建つ」を要求しない**のは、Lean の API 変更で建たなくなるのは**正常**だから。
判定するのは「**建たないときに何が起きるか**」— `extractor-mismatch` (X5) が見ているのは
「違う toolchain のバイナリを使ったとき」で、「**新しい toolchain でソースから建てたとき**」ではない。

## 4. 撤退ライン

- **U1**: GitHub の rate limit に当たったら root ごと 1 本に落とす (39 req)。認証は要らないはず。
  **叩いた本数と 200 の本数を両方記録する** — 「0 本叩いて 0 本失敗」を緑と読まないため
- **U3**: `windows-latest` で deno + puppeteer が動かなければ、**そこで止めて事実を記録する**
  (「Windows は測れなかった」は「Windows は大丈夫」ではない)
- **U4**: ASan 込みのビルドが通らなければ、**リーク検査だけ Valgrind 相当に落とさない** —
  別の道具は別の主張になる。落ちた事実を書く
- **U5**: 新しい toolchain の Mathlib が無いので、**対象は `e2e/micro`** (Mathlib 非依存)。
  「Mathlib 依存パッケージが新しい Lean で通る」までは主張しない

## 5. この計画が外れるとしたら

- **U1 が全部 200 で返る** — ありうる。その場合の収穫は「27 root の版固定リンクは実在する」
  という**事実そのもの**で、外れではない。ただし**行アンカーの正しさは HTTP では判定できない**
  (GitHub は存在しない行番号でもページを返す) ので、**主張は「URL が実在する」まで**
- **U2 で 25 件が全部きれいに解決する** — その場合「索引方式は所有モジュールを一意に決めない」
  という指摘は**出力には出ていない**ことになる。**指摘を消すのではなく、出力に出ない条件を書く**
