## 3. Approach

**同じ作業を 2 回やらないために、3 つの束に分けて順に通す。**

束が要るのは 2 つの理由による。

1. **IR schema を上げる変更をまとめる。** c / e / f-抽出 はどれも extractor と
   `litedoc4-ir` に触る。schema を 2 回上げると凍結フィクスチャの検査を 2 回やり直すことになる。
   **schema 4 → 5 を 1 回だけ**にする。
2. **描画の凍結フィクスチャを壊す変更をまとめる。**
   `crates/litedoc4-render/tests/data/*-expected.json` は**プロトタイプとの byte 一致**を
   凍結したもの (PROVENANCE.md)。HTML を 1 バイトでも変えると全部落ちる。
   だから **HTML を変える項目を最後の束に集め、再凍結を 1 回**にする。

| 束 | 項目 | 性質 |
|---|---|---|
| **A** | b, g | 既定の HTML を動かさない。単独で出せる |
| **B** | c, e-抽出, f-抽出 | IR schema 4 → 5。後方互換に足すだけ |
| **C** | a, d, e-描画, f-描画, i, 再凍結 | HTML が変わる。最後に 1 回再凍結 |

順序は **A → B → C**。A は誰にも依存しない。C は B が出す新フィールドを使う。

各項目に必ず 3 点を付ける。**付かないものは入れない**:

1. **落ちたときに何が壊れたか 1 行で言えるゲートかテスト。** 対象リポジトリを読むものは
   テストではなくゲート (`tools/*-gate.sh`)。新しいゲートは**必ず一度落としてから**通す。
2. **撤退ライン** — 何が起きたらこの設計をやめるか。
3. **数字を動かすなら実測ログ** (`benchmarks/results/`)。

### 凍結フィクスチャの扱い【決定 1】

`*-expected.json` は**移設の証拠**として凍結されている。移設は M1〜M8 で完了しており、
**新機能で出力が変わるのは当然**なので、束 C で役割を
**「移設の証拠」から「自分の出力に対する回帰基準」へ 1 回だけ切り替える**。

切り替えは 3 手順を踏む。**JSON を手で編集しない** (PROVENANCE.md の禁止事項):

1. **再生成手段を HEAD に置く** — `LITEDOC4_BLESS=1 cargo test` で expected を書き直す。
   今は再生成手段が HEAD に無く `experiments-frozen` からの復元が要る。これを解消する
   こと自体が改善で、以後フィクスチャは腐らない。
2. **差分を全件レビューする。** 変わったファイルごとに「どの項目のどの変更で変わったか」を
   1 行で書く。**説明できない差分が 1 つでもあれば止める。**
3. **PROVENANCE.md を書き換える** — 何の凍結値なのかが変わるので。
   `docgen4-linked-expected.json` は**別扱い**: これは doc-gen4 の出力が期待値なので、
   数式 (項目 a) が触る可能性がある。**触るなら doc-gen4 側の oracle
   (`tests/oracle/dump-html-linked.lean`、HEAD にある) を回して取り直す**、
   こちらの出力で上書きしない。

## 4. 項目別

### A-1 (b) 依存宣言のリンク先を選べるようにする

**測ってある**: `benchmarks/results/deps-link-rot-2026-08-19.txt`。
外部リンクの母数は 527 宣言 (Mathlib 396 + Init 130 + Lean 1)、2 か月 pin で死にリンク
0/396【実測】、12 か月 pin での期待値 10.3/396【外挿】。
宣言表は gzip 5.7 MB【実測】なので**全件検証が現実的**。

- **CLI**: `--deps-docs-url <Root>=<url>` (repeatable)、
  `--deps-docs-index <url|path>` (既定は `<url>/declarations/declaration-data.bmp`)。
  **どちらも渡さなければ今の挙動** (版固定 GitHub ソース)。
- **規則は 1 本**: 宣言表を引けたら、**名前が表に在るものだけ** docs へ、
  無いものは版固定ソースへ。表が引けなければ**全部ソース**。
  「あれば docs、無ければソース」というフォールバックではなく、
  **検証の結果に従うという 1 本のルール**。
- **1 行出す**: `deps  Mathlib: 396 名中 394 を docs へ、2 は表に無いのでソースへ`。
  黙って挙動が変わらないこと。
- **触るファイル**:
  - 新規: 宣言表の取得と検証 (`crates/litedoc4/src/deps_docs.rs`)。**ネットワークは
    `litedoc4` crate 側だけ** — `litedoc4-render` はネットを知らず、名前集合を受け取る。
  - `crates/litedoc4-render/src/external.rs` — 今 base が空/有りの 2 状態。docs base を持つ
    第 3 の状態を足す (「第 3 の状態」の議論がこのファイルの doc に既にある)。
  - `crates/litedoc4-render/src/autolink.rs` の `NameIndex::link_to` —
    **リンク 3 形の唯一の判断箇所**。判断を 1 箇所に集める規則どおり、ここだけを変える。
  - `crates/litedoc4/src/build.rs` — フラグ。
- **増分**: 検証結果は**描画キーに入れる** (`litedoc4_incr::render_key`)。
  `ExternalLinks::digest` と同じ理屈で、表が変われば全リンクの href が変わる。
  入れ忘れると「表を差し替えたのに再描画しない」になる。
- **テスト (機材ゼロ)**: 小さな宣言表 JSON をフィクスチャにして、在る名前と無い名前で
  リンクが変わることを両方向で検査。表が壊れている場合の拒否も。
- **ゲート (ネット要、`tools/deps-docs-gate.sh`)**: 実際に mathlib4_docs の表を引いて
  サイトを建て、生成された docs リンクを**全件 HTTP で確認して 404 が 0 件**。
  **一度落とす方法**: 表に無い名前を 1 つ注入して、そのリンクがソースに落ちることを確認
  (落ちなければゲートが嘘)。
- **撤退ライン**: 宣言表の形式が変わって読めない → **推測しない**。形を検査して違えば拒否し、
  全部ソースに落ちる。取得に 30 秒以上かかる → 既定で使わない。

### A-2 (g) `watch` + ローカルサーバ

**根拠**: #389 (open)「Rust の docs はミリ秒で建つのに」/ #404「10 分ハングに見えた」。
litedoc4 は no-op 再ビルド 0.31 s / 1 宣言追加 4.35 s を既に出している。
**足りないのはファイル監視と HTTP サーバだけで、新しいアルゴリズムは要らない。**

- **CLI**: `litedoc4 watch --root <repo> --out <dir> [--port <n>] [--extractor-bin …]`。
- 既存の `incremental --serve` (常駐 extractor、`crates/litedoc4/src/resident.rs`) の上に載せる。
  常駐しているので 2 回目以降は環境ロードを払わない。
- **`lake build` はしない**【判断】。今の分担 (建てるのは利用者/action、litedoc4 は olean を
  読むだけ) を watch でも変えない。olean が新しくなったことは既存の ledger が判定する。
  → README に「別窓で `lake build` を回す」と書く。
- **ゲート (`tools/watch-gate.sh`)**: ファイルを 1 つ触って、**再抽出モジュール数 = 1、
  再描画ページ数 = 影響ページ数**であること。**壁時計でゲートしない** (page cache で 5 倍動く)。
  **一度落とす方法**: 触っていないファイルを触ったことにして、再抽出数が 0 でないことを見る。
- **撤退ライン**: ファイル監視の挙動が OS で割れる → `notify` crate 1 本。
  **ポーリングにフォールバックしない** (経路が 2 本になる)。動かない OS は名前を出して拒否。

### B-1 (c) `sorry` / `sorryAx` 依存の可視化

**根拠**: #270 (open, 2025-03)。「mathlib には関係ないが、形式化途中のプロジェクトでは欲しい」
と書かれていて、**その利用者層が litedoc4 の対象そのもの**。

- **抽出**: `Lean.collectAxioms` で宣言ごとの公理集合を取り、`sorryAx` を含むかを見る。
  直接 `sorry` を書いたか (宣言自身が `sorryAx` を含み、かつ本体に現れる) と、
  推移的に依存するだけかを分ける。
- **IR**【決定 2】: `axioms` の全列挙ではなく **`sorry: "direct" | "transitive"` の 2 値、
  無ければキーごと省略**にする。理由は、Mathlib 依存の宣言はほぼ全部が
  `Classical.choice` / `propext` / `Quot.sound` を持つので、全列挙は情報量が無いのに
  IR を太らせるため。**公理の全列挙は未検証項目に落とす** (§8)。
- **性能が本丸**: `collectAxioms` は推移閉包。4,584 宣言で**抽出時間が何割増えるかを測る**。
  ログ: `benchmarks/results/axioms-<date>.txt`。
- **テスト**: `e2e/micro` に 3 形を足す — 直接 `sorry`、`sorry` を使う定理に依存するもの、
  どちらでもないもの。**Mathlib 非依存で書けるので CI で回る。**
- **ゲート**: `tools/e2e-micro.sh` に、3 形が IR で区別されることを足す。
  **一度落とす方法**: 3 形のうち 1 つの期待値を反転させる。
- **撤退ライン**: 抽出時間が **+10% を超えたら既定オフ** (`--axioms` で opt-in)。
  それでも `e2e/micro` では常に検査する。

### B-2 (e) 属性の構造化

**根拠**: #331 (open)「`@[stacks 07BJ]` が docs に出ない」。

- 今 `attrs: Vec<String>` で `"deprecated Foo"` のような文字列を持ち、描画は
  `crates/litedoc4-render/src/decl.rs:590` で `@[a, b]` と素のテキストに落としている。
- **やること**: IR を `{name, value}` の構造に変える (schema 5、`#[serde(default)]` で
  古い IR も読める)。描画側で
  (1) `deprecated <Name>` を**その宣言へのリンク**にする、
  (2) 属性ごとに識別できる形で出す (CSS で区別できるように)。
- **`@[stacks]` そのものは別問題**。extractor の `getAllAttributes`
  (`extractor/Extract.lean:845`) は doc-gen4 の**固定リスト** (tags / enums / parametric /
  custom) で、Mathlib が定義した属性の**値**は読めない。
  **一般の属性値を Lean から読めるかは未検証**なので §8 に落とす。
  この項目で閉じるのは「今 IR にある属性を構造化してリンクする」ところまで。
  **#331 が閉じるとは書かない。**
- **テスト**: `deprecated` を持つ宣言のリンク先が正しいこと。`e2e/micro` に 1 形足す。
- **撤退ライン**: なし (純粋な足し算)。ただし IR が太るなら `{name, value}` ではなく
  文字列のまま描画側で分割する案に戻す。

### B-3 (f) 自動生成宣言のグルーピング

**根拠**: #163 (open)「`@[ext]`/`@[simps]`/`to_additive` 由来の宣言が本体より前に出る」、
#184「自動生成の projection が出ない」。

- **まず調べる**: IR を変えずにできる可能性がある。`Decl::index` の doc に
  「このパッケージには **(line, col) を共有する宣言が 2 つある**」と既に書いてあり、
  自動生成された宣言は元宣言と同じ `declRange` を持つ。
  **同じ (line, col) を共有する群を親子とみなせるか**を対象 422 モジュールで確かめる。
- **できるなら束 B から外して束 C だけで済ませる** (IR を触らない)。
  できないなら extractor で由来を出す (schema 5 に相乗り)。
- **調査の出口を決めておく**: (line, col) 共有で親子が決まらない例が出たら、
  **推測で畳まない**。畳めない群はそのまま並べる。
- **テスト**: `e2e/micro` に `@[ext]` を持つ structure と `@[simps]` を持つ def を足し、
  親子が期待どおりに畳まれること。
- **撤退ライン**: 親の判定が曖昧な群が対象で 1 つでも出たら、**その群は畳まない**
  (畳めた群だけ畳む)。「たぶん親」を描かない。

### C-1 (a) docstring の数式

**根拠**: README の「No」の 1 つ目。doc-gen4 は MathJax をクライアントで走らせている。
Mathlib 依存パッケージの docstring は数式を含む。

- **方式【決定 4】: ビルド時に LaTeX → MathML に変換して HTML に焼く。**
  Rust のクレートは **`pulldown-latex` を使う**【調査 2026-08-19】 — v0.8.0、
  2026-07-28 更新、依存は `bumpalo` 1 本 (`regex` は optional)。
  `latex2mathml` は 2020 年で更新が止まっており、`katex` クレートは JS エンジンを
  抱き込むので、依存をほとんど持たないこの木には入れない。
  - **node を実行時に要求しない** — 「利用者は node を払わない」という既存の決定を保つ
    (node は `build.rs` が vite を回すときだけ、つまり開発者と CI のビルド時だけ)。
  - **閲覧側に JS を足さない** — 生成の速さと閲覧の軽さは別の話で、
    ここで数百 KB を足すと後者を失う。MathML はブラウザが自前で描く。
- **変換に失敗した数式は素のテキストに戻す。壊れた MathML を出さない。**
  失敗件数をビルドログに 1 行出す。
- **必ず実測する**: 対象 422 モジュールで (1) 数式を含む docstring の件数、
  (2) 変換成功率、(3) 生成時間の増分。ログ: `benchmarks/results/mathml-<date>.txt`。
- **テスト**: `crates/litedoc4-md` に変換のユニットテスト。`e2e/micro` に
  インライン `$…$`・ブロック `$$…$$`・壊れた LaTeX の 3 形。
- **ゲート**: 既存のブラウザゲート (`tools/check-site-browser.ts`) に、
  MathML が実際に描画されている (幅を持つ) ことを足す。
  **一度落とす方法**: MathML を素のテキストに差し替えて落ちることを見る。
- **撤退ライン**: 変換クレートが対象の docstring で**落ちる/崩れる**、または主要ブラウザで
  描画が破綻する → **クライアント側 KaTeX に切り替える** (静的アセットなので node は
  要らないまま)。切り替えたら README の「閲覧側に JS を足さない」という主張を消す。

### C-2 (d) 宣言単位の逆引き

**根拠**: #77, #63。doc-gen4 は「blueprint と David's docs でやれ」と閉じた —
**閉じた理由は Mathlib 全体では母数が爆発するから**で、自パッケージ限定なら現実的。
(a) と同じく、**「自分のパッケージだけ」という制約が有利に働く**例。

- `Decl::refs` (defining module + name) を全モジュール分集めて逆引きする。
- **置き場所**: `crates/litedoc4-global` (全体を見るクレート。`search_index.rs` と同じ位置づけ)。
  増分は既存の `delta.rs` の形に乗せる — 逆引きは全体索引なので 1 モジュールの変更で動く。
- **表示**: 宣言ごとに `Used by (N)`。**N が大きい場合の扱いはサイズを測ってから決める**
  (全件を折りたたむか、上位のみか)。
- **不変量ゲート (`tools/usedby-gate.sh`)**: **A が B を参照する ⟺ B の逆引きに A が居る**
  を両方向で突き合わせる。これは「別経路が同じ答えを出すか」型のゲートで、外部オラクルが要らない。
  **一度落とす方法**: 逆引きから 1 件消して、両方向の差として出ることを確認。
  **両方向が同時に落ちたら比較器を疑う** (文字集合の違い) — 2026-08-17 に踏んだ形。
- **撤退ライン**: サイト全体のバイト数が有意に増える (1 サイト約 60 MB が基準) →
  件数だけ表示してリストは別ファイルに出す。

### C-3 (i) サイト設定 (index ページ / タイトル)

**根拠**: #43 (2022-02 から open)、#102。

- **`--title` フラグは置かない**【決定 3】。`frame.rs:66-70` の理由 (3 つの描画コマンドの
  どれかで付け忘れると食い違う) は正しい。代わりに **`--root` に置く設定ファイル
  `litedoc4.toml`** を読む。フラグと違い**パッケージの一部なので忘れられ方が違う**。

  ```toml
  title = "MyPkg"
  index = "docs/index.md"   # サイトの index に差し込む Markdown
  ```

- **3 つの描画経路が同じ答えを出すこと**が条件。`build` が解決して state に書き、
  `render` / `site` はそれを読む。**解決を 1 箇所に集める。**
- **ゲート**: 同じパッケージを `build` / `site` / `render` の 3 経路で描き、
  `<title>` と index の中身が一致すること。**一度落とす方法**: 1 経路だけ設定を読ませない。
- **撤退ライン**: 設定ファイルが 3 経路で食い違う設計にしかならない → **項目ごと落とす**
  (今の派生タイトルのままにする)。食い違うくらいなら設定できない方がよい。

### C-4 フィクスチャの再凍結
