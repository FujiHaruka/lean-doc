## 3. Approach

**同じ作業を 2 回やらないために、3 つの束に分けて順に通す。**

束が要るのは 2 つの理由による。

1. **IR schema を上げる変更をまとめる。** c / e / f-抽出 はどれも extractor と
   `litedoc4-ir` に触る。schema を 2 回上げると凍結フィクスチャの検査を 2 回やり直すことになる。
   **schema 4 → 5 を 1 回だけ**にする。
2. **描画の凍結フィクスチャを壊す変更をまとめる。**
   `crates/litedoc4-render/tests/data/*-expected.json` は**プロトタイプとの byte 一致**を
   凍結したもの (PROVENANCE.md)。HTML を 1 バイトでも変えると全部落ちる。
   だから **HTML を変える項目を最後の束に集め、再凍結を 1 回**にする。

| 束 | 項目 | 性質 |
|---|---|---|
| **A** | b, g | 既定の HTML を動かさない。単独で出せる |
| **B** | c, e-抽出, f-抽出 | IR schema 4 → 5。後方互換に足すだけ |
| **C** | a, d, **c-描画**, e-描画, f-描画, i, 再凍結 | HTML が変わる。最後に 1 回再凍結 |

順序は **A → B → C**。A は誰にも依存しない。C は B が出す新フィールドを使う。
**schema を 5 に上げるのは束 B の最初の 1 件だけ**で、以降の項目は
`#[serde(default)]` でフィールドを足すだけ (版は上げ直さない)。

各項目に必ず 3 点を付ける。**付かないものは入れない**:

1. **落ちたときに何が壊れたか 1 行で言えるゲートかテスト。** 対象リポジトリを読むものは
   テストではなくゲート (`tools/*-gate.sh`)。新しいゲートは**必ず一度落としてから**通す。
2. **撤退ライン** — 何が起きたらこの設計をやめるか。
3. **数字を動かすなら実測ログ** (`benchmarks/results/`)。

### 凍結フィクスチャの扱い【決定 1】

`*-expected.json` は**移設の証拠**として凍結されている。移設は M1〜M8 で完了しており、
**新機能で出力が変わるのは当然**なので、束 C で役割を
**「移設の証拠」から「自分の出力に対する回帰基準」へ 1 回だけ切り替える**。

切り替えは 3 手順を踏む。**JSON を手で編集しない** (PROVENANCE.md の禁止事項):

1. **再生成手段を HEAD に置く** — `LITEDOC4_BLESS=1 cargo test` で expected を書き直す。
   今は再生成手段が HEAD に無く `experiments-frozen` からの復元が要る。これを解消する
   こと自体が改善で、以後フィクスチャは腐らない。
2. **差分を全件レビューする。** 変わったファイルごとに「どの項目のどの変更で変わったか」を
   1 行で書く。**説明できない差分が 1 つでもあれば止める。**
3. **PROVENANCE.md を書き換える** — 何の凍結値なのかが変わるので。
   `docgen4-linked-expected.json` は**別扱い**: これは doc-gen4 の出力が期待値なので、
   数式 (項目 a) が触る可能性がある。**触るなら doc-gen4 側の oracle
   (`tests/oracle/dump-html-linked.lean`、HEAD にある) を回して取り直す**、
   こちらの出力で上書きしない。

## 4. 項目別

### A-1 (b) 依存宣言のリンク先を選べるようにする

**測ってある**: `benchmarks/results/deps-link-rot-2026-08-19.txt`。
外部リンクの母数は 527 宣言 (Mathlib 396 + Init 130 + Lean 1)、2 か月 pin で死にリンク
0/396【実測】、12 か月 pin での期待値 10.3/396【外挿】。
宣言表は gzip 5.7 MB【実測】なので**全件検証が現実的**。

- **CLI**: `--deps-docs-url <Root>=<url>` (repeatable)、
  `--deps-docs-index <Root>=<url|path>` (repeatable、既定は
  `<url>/declarations/declaration-data.bmp`)。**どちらも渡さなければ今の挙動**
  (版固定 GitHub ソース)。`build` が解決結果を `<out>/work/deps-docs-map.json` に書き、
  描画する他のコマンドは `--deps-docs-map <file>` でそれを読む (再導出させない)。
- **規則は 1 本**: 宣言表を引けたら、**名前が表に在るものだけ** docs へ、
  無いものは版固定ソースへ。表が引けなければ**全部ソース**。
  「あれば docs、無ければソース」というフォールバックではなく、
  **検証の結果に従うという 1 本のルール**。
- **1 行出す**: `deps  Mathlib: 396 名中 394 を docs へ、2 は表に無いのでソースへ`。
  黙って挙動が変わらないこと。
- **触るファイル**:
  - 新規: 宣言表の取得と検証 (`crates/litedoc4/src/deps_docs.rs`)。**ネットワークは
    `litedoc4` crate 側だけ** — `litedoc4-render` はネットを知らず、名前集合を受け取る。
  - `crates/litedoc4-render/src/external.rs` — 今 base が空/有りの 2 状態。docs base を持つ
    第 3 の状態を足す (「第 3 の状態」の議論がこのファイルの doc に既にある)。
  - `crates/litedoc4-render/src/autolink.rs` の `NameIndex::link_to` —
    **リンク 3 形の唯一の判断箇所**。判断を 1 箇所に集める規則どおり、ここだけを変える。
  - `crates/litedoc4/src/build.rs` — フラグ。
- **増分**: 検証結果は**描画キーに入れる** (`litedoc4_incr::render_key`)。
  `ExternalLinks::digest` と同じ理屈で、表が変われば全リンクの href が変わる。
  入れ忘れると「表を差し替えたのに再描画しない」になる。
- **テスト (機材ゼロ)**: 小さな宣言表 JSON をフィクスチャにして、在る名前と無い名前で
  リンクが変わることを両方向で検査。表が壊れている場合の拒否も。
- **ゲート (ネット要、`tools/deps-docs-gate.sh`)**: 実際に mathlib4_docs の表を引いて
  サイトを建て、生成された docs リンクを**全件 HTTP で確認して 404 が 0 件**。
  **一度落とす方法**: 表に無い名前を 1 つ注入して、そのリンクがソースに落ちることを確認
  (落ちなければゲートが嘘)。
- **撤退ライン**: 宣言表の形式が変わって読めない → **推測しない**。形を検査して違えば拒否し、
  全部ソースに落ちる。取得は `--max-time 120` で打ち切る (実測 0.63 s なので、
  そこに近づく回線は終わらない回線)。**ハングさせない** — この機能が拾った要望の 1 つが
  doc-gen4 #404「ハングする」なので、直しがハングを足したら本末転倒。

**実装で決まったこと (2026-08-19)**:

- **描画キーは「解決した entry」を hash する。表のバイト列ではない。**
  帰結: このパッケージが**新しく参照し始めた依存名**が現れた最初のビルドで digest が動き、
  全ページを描き直す (Lean は走らない)。表のバイト列を hash する案だと、その新しい名前は
  ページが他の理由で触られるまでソースを指したままになる。**うるさい方を採った。**
- **`.lidx` 経由でしか届かない名前** (docstring だけが言及する依存宣言) は要求集合に入らないので
  ソースリンクのまま。**出力の 1 行が自分の分母を名乗る**のはこのため。
- **`curl` に丸投げする**。HTTP クレートを足さない (この木の依存は `serde_json` と `sha2` だけ)。
  `curl` が無ければ名前を出して拒否。**`curl` の終了コードをパーサのエラーより先に読む**
  (失敗した取得は空の body を返すので、パーサが先に「JSON ではない」と言う — 真だが無用)。
- **`--deps-docs-map` は「描画する経路」と「描画キーを計算する経路」の全部に置いた** —
  `site` / `render` / `incremental` / `ledger build` / `ledger check` / `links`。
  描画側だけに置くと `ledger` が地図を見られず、`renderKey.externalLinks` が `build` の
  記録と食い違って**「変わった / 変わっていない」を真でない理由で答える**。
  付け方は 1 本 (`with_dependency_docs`) で、2 本目の経路を作らない。
- **ゲートは規則の両枝を見る** (`tools/deps-docs-gate.sh`)。
  枝 1 (docs へ行った名前) は**アンカーまで**見る — ページだけ見ると
  **生きているモジュールの中で改名された宣言**を通す。判定は宣言表ではなく
  **サーバが返した HTML の `id` 属性**に対して行う (表は build の入力なので、
  表と突き合わせると「解決器が表を正しく写したか」を「リンクが生きているか」と
  言い換えることになる)。
  枝 2 (ソースに落ちた名前) は、その名前の docs ページを指す href が
  **サイトのどこにも無いこと**と、リンクされているなら版固定ソースであることを見る。
  **ページが 200 でも捕まる**のがここで、枝 1 には見えない。
  **既定で Init も docs に向ける** — この対象で fallback が発火する唯一の root で、
  Mathlib だけだと枝 2 が空のまま「ok」と言うゲートになる【実測】。
  数字は `benchmarks/results/deps-docs-2026-08-19.txt`。

### A-2 (g) `watch` + ローカルサーバ

**根拠**: #389 (open)「Rust の docs はミリ秒で建つのに」/ #404「10 分ハングに見えた」。
litedoc4 は no-op 再ビルド 0.31 s / 1 宣言追加 4.35 s を既に出している。
**足りないのはファイル監視と HTTP サーバだけで、新しいアルゴリズムは要らない。**

- **CLI**: `litedoc4 watch --root <repo> --out <dir> [--port <n>] [--interval <ms>]`
  ＋ `build` の全フラグ。
- **`lake build` はしない**【判断】。今の分担 (建てるのは利用者/action、litedoc4 は olean を
  読むだけ) を watch でも変えない。olean が新しくなったことは既存の ledger が判定する。
  → README に「別窓で `lake build` を回す」と書く。
- **ゲート (`tools/watch-gate.sh`)**: モジュールを 1 つ stale にして、**再抽出モジュール数 = 1、
  再描画ページ数 = 影響ページ数**であること。**壁時計でゲートしない** (page cache で 5 倍動く)。

**実装で決まったこと (2026-08-19)**:

- **常駐 extractor はパスをまたいで生き残らない**【実測、stage 6a → `resident.rs` の見出し】。
  上の計画は「常駐しているので 2 回目以降は環境ロードを払わない」と書いていたが、**これは誤り**。
  Lean は import 済み環境からモジュールを差し替えられない (`Extract.lean:2716-2721`)。
  そして**パスが抽出するのは olean が動いたときだけ**なので、前のパスから持ち越したサーバは
  定義上「いま stale になった環境を抱えたサーバ」になる。持ち越しは
  **抽出するパスでは不正**、**抽出しないパスでは無意味** (`Resident` は遅延起動なので、
  何も抽出しないパスはサーバを起動しない)。常駐が買っているものは変わらず買えている —
  **1 パスの中**の ownership/merge ラウンドが 1 回の import を共有する。
  帰結: 1 モジュール編集の実測は環境ロード込みで、`benchmarks/results/watch-2026-08-21.txt`。
- **監視はタイマーで ledger に訊く。`notify` は入れなかった。** 撤退ラインは
  「OS で割れたら `notify` 1 本、ポーリングにフォールバックしない」だったが、
  **ポーリングはフォールバックではなく唯一の経路**として選んだ。理由は
  (1) イベントは所詮ヒントで、答えは結局 ledger が出す (経路が 2 本になるのは
  イベント側だけ)、(2) 実測してコストが小さい — 対象 422 モジュール (olean 228 MB) の
  1 回の `check_ledger` が **warm 0.13 s / cold 0.37 s**【実測】。
  既定 `--interval` は 1000 ms、下限 100 ms。**払っているものは隠さず 1 行に出す**
  (heartbeat が「ask に何秒かかったか」を印字する)。
- **watch は `build` をループしているだけ**。パーサは 1 本
  (`build::parse(args, Some(&mut watch::Flags))`)、`Request` は 1 個、
  各パスは `build::run(&request)` を呼ぶ。**2 本目の「サイトを建てる経路」を作らない。**
- **1 インターバルの静けさを待ってから抽出する。** ledger の答えが前パスと同じになって
  初めて動く。`lake build` が olean を書いている最中に抽出すると、半分ずつ 2 つの世界から
  できたサイトになるか、`Resident` の generation guard が exit 3 で止める。
  代償は 1 インターバルの遅延で、**待っている間は何を待っているか毎回言う** (#404 の形)。
- **失敗したパスは、世界がもう一度動くまで再試行しない。** 毎秒 3 GB の import を
  やり直すことになるため。ただし**最初のパスの失敗は致命** (まだサイトが無い)。
- **`--deps-docs-url` / `--deps-docs-index` は watch では名指しで拒否**。
  A-1 の解決は「その run の IR に対して 5.7 MB の宣言表を 1 回引く」なので、ループは
  「毎回引く」か「古いまま使う」しか選べない。
- **`--lib` と `--source-url` は起動時に 1 回だけ確定させる。** どちらも renderKey の入力で、
  トリガ側と実行側が別々に導出すると「鍵が動いた」と互いに言い合って毎パス全描画になる。
  帰結: **セッション中の `git commit` はページのソースリンクを動かさない** (watch を再起動する)。
- **サーバは生成物をそのまま返す** (`crates/litedoc4/src/httpd.rs`、std だけ、依存追加なし)。
  live-reload スクリプトは注入しない【判断】 — 見ているものと publish するものが
  別ファイルになるため。代わりに `Cache-Control: no-store` を付ける (#389 は
  「更新されない」なので、ブラウザのキャッシュから 200 を返されたら台無し)。
  既定ポート **8484**、127.0.0.1 のみ、**塞がっていたら名前を出して拒否 (次の空きに移らない)**。
- **ゲートは olean を触らない。** `touch` は mtime しか動かさず ledger は内容を hash する。
  olean を書き換えるのは計測対象への書き込みで禁止。だから
  `litedoc4 ledger touch` (この用途のために既にある) で ledger 側に注入する。
  見る整数は `modulesExtracted` / `pagesRendered` / `extractorRequests` = 1/1/1 と
  **render-set.txt がその名前 1 件であること**、そして
  **`impact` が選んだページ数と renderer が書いたページ数が一致すること** (別経路の 2 数)。
  **一度落とす方法は 2 つ**: `--inject wrong-module` (別のモジュールを stale にする —
  1/1/1 は緑のままで、名前の照合だけが捕まえる) と `--inject no-touch`
  (何も触らずに再ビルドを待ち、タイムアウトが答えになること)。
  **実測ログは `benchmarks/results/watch-2026-08-21.txt`。**
- **ゲートは「他の watch が居たら始めない」**【実測 2026-08-21】。`watch` は
  起動したシェルより長生きするので、中断したセッションの取り残しが同じ作業領域を
  掴んだままになる。そうすると (1) ゲートのビルドが読んでいる IR を書き換えて
  `EOF while parsing a value at line 1 column 0` になり (増分パイプラインは IR
  モジュールをその場で上書きする — `litedoc4-incr::merge` の `copy`/`write`。
  **書き換えは atomic ではない**)、(2) 後始末の削除中にファイルを作り直して
  `rm: Directory not empty` になる。**どちらも「ゲートが壊れている」ように見える。**
  → 冒頭で pid と command line を名指しして **exit 2 で拒否する。殺さない**
  (他人のプロセスを殺すのはゲートの仕事ではない)。
  **そして拒否した作業領域は消さない** — 拒否経路でも `rm -rf` していて、
  他のプロセスが使っているディレクトリを実際に消した【実測】。所有権のフラグを
  ゲート通過後に立て、それが立つまで cleanup は何も消さない。
- **撤退ライン**: ポーリングのコストが対象で無視できなくなる (idle パスが interval の
  1 割を超える) → `--interval` の既定を上げる。それでも足りなければ `notify` 1 本を入れ、
  **ポーリングは消す** (2 本にしない)。

### B-1 (c) `sorry` / `sorryAx` 依存の可視化

**根拠**: #270 (open, 2025-03)。「mathlib には関係ないが、形式化途中のプロジェクトでは欲しい」
と書かれていて、**その利用者層が litedoc4 の対象そのもの**。

- **抽出**: `Lean.collectAxioms` で宣言ごとの公理集合を取り、`sorryAx` を含むかを見る。
  直接 `sorry` を書いたか (宣言自身が `sorryAx` を含み、かつ本体に現れる) と、
  推移的に依存するだけかを分ける。
- **IR**【決定 2】: `axioms` の全列挙ではなく **`sorry: "direct" | "transitive"` の 2 値、
  無ければキーごと省略**にする。理由は、Mathlib 依存の宣言はほぼ全部が
  `Classical.choice` / `propext` / `Quot.sound` を持つので、全列挙は情報量が無いのに
  IR を太らせるため。**公理の全列挙は未検証項目に落とす** (§8)。
- **性能が本丸**: `collectAxioms` は推移閉包。4,584 宣言で**抽出時間が何割増えるかを測る**。
  ログ: `benchmarks/results/sorry-2026-08-21.txt`。
- **テスト**: `e2e/micro` に 3 形を足す — 直接 `sorry`、`sorry` を使う定理に依存するもの、
  どちらでもないもの。**Mathlib 非依存で書けるので CI で回る。**
- **ゲート**: `tools/e2e-micro.sh` に、3 形が IR で区別されることを足す。
  **一度落とす方法**: 3 形のうち 1 つの期待値を反転させる。
- **撤退ライン**: 抽出時間が **+10% を超えたら既定オフ** (`--axioms` で opt-in)。
  それでも `e2e/micro` では常に検査する。

**実装で決まったこと (2026-08-21)**:

- **`collectAxioms` は推移閉包を歩かない。撤退ラインは発火せず、既定オンで確定。**
  Lean は `PersistentEnvExtension` (`Lean/Util/CollectAxioms.lean` の
  `exportedAxiomsExt`) を持っていて、**宣言ごとの公理配列は olean を書くときに
  計算済み**。**import された定数**に対する `collectAxioms` はその配列への
  binary search で、式を 1 つも歩かない。この抽出器が見る宣言は全部 import 側
  (`importModules`) なので、**計画が「共有すべき」と書いていたメモは、olean を
  建てた者が既に 1 回払っている**。v4.31.0 / v4.32.2 / v4.33.0 で同一実装。
  対象 422 モジュール / 4,584 宣言で **phase 0.006 s = `total` 5.916 s の 0.10%**
  【実測、warm、交互 5 対 → `benchmarks/results/sorry-2026-08-21.txt`】。
- **`"direct"` の判定だけが式を歩くので、答えが `"direct"` になり得るときしか訊かない。**
  公理配列に `sorryAx` が無い宣言は 2 値のどちらでもないので binary search だけで
  答える。**費用はパッケージの大きさではなく汚染された宣言数に比例する。**
  **天井を測ってある**: 早期脱出を外して全宣言で式を歩かせると **0.594 s = +10.0%**
  【実測、使い捨てバイナリ、IR は製品版とバイト一致】。**撤退ラインちょうど**なので、
  早期脱出は最適化ではなく設計の一部。
- **対象パッケージには `sorry` が 1 件も無い** (0 direct / 0 transitive)【実測】。
  だから上の 0.10% は**安い側しか測っていない** — 本文を `\bsorry\b` で引くと 24 ファイル
  当たるが全部散文で、抽出器の答えと一致する (別経路の突き合わせ)。
  分類が実際に汚染宣言で動くことは `e2e/micro` が持つ (1 direct / 1 transitive)。
- **ablation は `--no-sorry`** (`--axioms` の opt-in ではない)。2 本の腕が
  **同じバイナリ**でなければ差は取れないので、既存の `--no-attrs` と同じ形にした。
  ablation 付きの IR は `index.json` に `ablations` が出て描画側が拒否する。
- **`sorry` の計算は解析ループの後の単独パス、シングルスレッド。**
  `--jobs` が答えに届かないこと (GATE 4 のバイト一致) が理由で、
  1 回の `MetaM` 実行の中で `results` を候補順に舐める。
- **`MIN_SCHEMA_VERSION` は 4 のまま据え置いた**【判断 2026-08-21】。書き手側は
  schema 5 に上がったが、**読み手の下限を 5 にすると
  `litedoc4-global/tests/data/global-expected.json` に凍結されている curated IR
  (入力側、`"schemaVersion":4`) を手で書き換えることになる**。凍結 JSON の手編集は
  §3【決定 1】の禁止事項で、再凍結は C-4 の 3 手順の仕事。
  代わりに**キーの 3 値性を型で持たせた** — `ModuleFile::sorry_of` が
  `SorryFact::{Unknown, Clean, Direct, Transitive}` を返し、`Unknown` は
  「schema 4 なので誰も訊いていない」。`Decl::sorry` を直接読むものは他に無い
  (`Member::is_direct` / `is_inherited` と同じ形)。
  **`MIN_SCHEMA_VERSION` を 5 に上げるのは C-4 と同じコミット**で、それまでは
  「キーが無い」と「schema が古い」が型で分かれている。
- **e2e フィクスチャは `Micro/Sorry.lean` を足した** (`Micro/Basic.lean` ではない —
  GATE 6 があのファイルに probe を追記するので、`sorry` 警告と混ざる場所に置かない)。
  ゲートは `tools/e2e-micro.sh` の **GATE 7**。**IR を読む** (束 B は抽出と IR だけで、
  まだどのページにも出ない)。**比較した本数を数え**、加えて
  **他の宣言が `sorry` を名乗っていないこと**を見る — 全部に `"transitive"` を返す
  分類器は肯定側 2 件を通ってしまう。

### B-2 (e) 属性の構造化

**根拠**: #331 (open)「`@[stacks 07BJ]` が docs に出ない」。

- 今 `attrs: Vec<String>` で `"deprecated Foo"` のような文字列を持ち、描画は
  `crates/litedoc4-render/src/decl.rs:590` で `@[a, b]` と素のテキストに落としている。
- **やること**: IR を `{name, value}` の構造に変える (schema 5、`#[serde(default)]` で
  古い IR も読める)。描画側で
  (1) `deprecated <Name>` を**その宣言へのリンク**にする、
  (2) 属性ごとに識別できる形で出す (CSS で区別できるように)。
- **`@[stacks]` そのものは別問題**。extractor の `getAllAttributes`
  (`extractor/Extract.lean:845`) は doc-gen4 の**固定リスト** (tags / enums / parametric /
  custom) で、Mathlib が定義した属性の**値**は読めない。
  **一般の属性値を Lean から読めるかは未検証**なので §8 に落とす。
  この項目で閉じるのは「今 IR にある属性を構造化してリンクする」ところまで。
  **#331 が閉じるとは書かない。**
- **テスト**: `deprecated` を持つ宣言のリンク先が正しいこと。`e2e/micro` に 1 形足す。
- **撤退ライン**: なし (純粋な足し算)。ただし IR が太るなら `{name, value}` ではなく
  文字列のまま描画側で分割する案に戻す。

**実装で決まったこと (2026-08-21)**:

- **線の形は `Ref` に倣った 2 要素配列 `[name, value]`**。オブジェクトを作らない。
  Rust 側は**両方の形を受ける** — 裸の文字列 (schema 4、および schema 4 の IR を
  テスト入力として抱えている凍結フィクスチャ) と 2 要素配列。**要素数が違う配列は拒否**する。
- **分割は extractor でやる。描画側で再分割しない。** 連結を作っているのは extractor で、
  境界を知っているのはそこだけ。実際 `deprecated` の値には空白・括弧・引用符が入り、
  `specialize` の値には角括弧が入る (`e2e/micro/Micro/Attrs.lean`)。
  **対象にはその形が 1 つも無い** — 163 出現 / 6 種類で、ほぼ全部が裸の名前【実測】 —
  ので、フィクスチャが唯一の検査場所。
- **IR の増分は +814 B / 15,093,293 B = +0.0054%**【実測 →
  `benchmarks/results/attrs-2026-08-21.txt`】。撤退ラインには遠い。
- **描画は 1 バイトも動かしていない** — `Attr::text` が 2 要素を schema 4 の連結に戻し、
  凍結フィクスチャが全部通る。値に対して何かする (`@[deprecated Foo]` を `Foo` への
  リンクにする) のは束 C。
- **ゲート GATE 8** (`tools/e2e-micro.sh`) は各宣言の `attrs` を丸ごと比べ、
  **実際に比較できた期待の本数**と、**他の宣言が同じ属性を主張していない本数**も数える
  (positive な期待だけでは「全部に色を付ける分類器」を捕まえられないため)。
  一度落とした実測: `specialize` の name/value 境界を 1 つずらすと **exit 1** で
  `GATE 8 FAIL  Micro.Attrs.applyTwice: attrs are [["specialize", "#[]"]],
  expected [["specialize #[]", ""]]` と両側を名指しする。

### B-3 (f) 自動生成宣言の由来

**B-0 の調査で前提が崩れたので書き直した**【実測 2026-08-21 →
`docs/plans/b0-generated-decls.md`】。**旧版の想定は 2 つとも誤りだった:**

1. 「`(line, col)` を共有する群を親子とみなせるか」→ **みなせない。**
   Lean の `declRange` は生成された宣言に**それを生成した属性トークンの位置**を与える。
   位置が指すのは**生成器であって親ではない**。候補規則 5 つを Mathlib 標本
   (10 モジュール / 2,786 宣言 / 144 群) で試して**全部落ちた** — 特に
   「親が群の中に居る」は **0 / 144**、**47 群は 2 つ以上の名前空間にまたがる**
   (畳むと無関係な兄弟を 1 つにする)。
2. 「#163 の症状 = 生成宣言が本体より前に出る」→ **両標本で 0 件**。
   v4.31.0 の `declRange` は docstring と属性を含むので、子は親の直後に来る。
   **実際に出ている症状は「親から離れて、無関係な宣言のブロックの中に落ちる」**
   (Mathlib 標本 188 / 224)。**旧版のまま実装すると、直すべき入力が 1 件も無いまま
   緑になるゲートを作る。**

**縮めた B-3**:

- **structure の projection (#184) はやることが無い** — IR に在り、190 件すべてが
  トップレベル宣言として存在し、`Suppressed::of_site` が単独ページを消すだけで
  アンカーは残る【実測】。**#184 は litedoc4 では欠陥ではない。**
- **`@[ext]` 由来だけ畳む。** 拡張が Lean core にあるので親を引ける。
  **`simps` / `to_additive` / `mk_iff` / `to_dual` / `alias` は畳まない** —
  拡張が Mathlib のもので、extractor を Mathlib に依存させると `e2e/micro` が
  回らなくなり CI のゲートが 1 本消える。
- **畳まない群には親を主張しない。** 代わりに「この宣言は `<位置>` の属性が生成した」と
  1 行出す。§6 の症状 (無関係なブロックに落ちる) はこれで読者の混乱が消え、
  **親を名乗らないので「たぶん親」を描かない**という出口条件に触れない。
- **IR の追加は `selectionRange` 1 つ** (schema 5)。生成と手書きの区別に要る。
- **ゲート**: 「生成宣言が無関係な宣言のブロックの中に落ちた件数」を数える
  (これが実在する症状)。**旧版の「親より前に出る件数」は数えない** — 0 件で緑になる。
  加えて**反証条件を検査する**: `declRange` の始点は Lean の実装依存なので、
  **「親より前に並ぶ件数」を約束している 3 版 (v4.31.0 / v4.32.2 / v4.33.0) で数え**、
  0 でなくなったら B-0 §6 を書き直す。
- **撤退ライン**: `selectionRange` を足しても「生成された」の判定が両標本で一致しなければ
  **B-3 ごと落とす**。`@[ext]` の由来を Mathlib 非依存で引けなければ落とす。
  曖昧な群が新しく 1 つでも出たら、その群は並べたまま。

**実装で決まったこと (2026-08-21)** 【実測 →
`benchmarks/results/generated-decls-2026-08-21.txt`】:

- **撤退ラインは踏まなかった。** `@[ext]` の判定は両標本で完全に一致した —
  Mathlib 標本の ext 形 **94/94**、計測対象 **3/3**、`e2e/micro` **10/10**。
  **誤った親を名乗った宣言は 3 標本とも 0 件。**
- **ただし `selectionRange == range` 単独では「生成された」にならない。**
  B-0 §11 の「これで範囲が属性トークンを指していると判定できる」は**両方向とも偽**で、
  この計測が否定した (B-0 §11 に追記済み): Mathlib 標本では `sel == range` の
  **779 件中 209 件 (26.8%)** が射影・constructor・macro 定義であり、逆に範囲が
  属性トークンを指しているのに `sel != range` になるものが **376 件**ある
  (Mathlib の `to_additive` が `selectionRange` に著者の書いた加法版の名前を入れるため)。
  計測対象ではさらに極端で **197 件中 195 件 (99.0%)** が「生成でないのに `sel == range`」。
  **判定は「拡張に居る」との合成でのみ成立する** — 合成は
  `extractor/Extract.lean` の `extOriginOf` 1 箇所に置いた。
- **出すのは「実現の入力」を 1 段だけ。** `P.ext` は structure `P` を、
  `P.ext_iff` は `P.ext` を指す。畳んで `P.ext_iff → P` にしない —
  `P.ext` が手書きの場合に structure を親と名乗ることになるため。連鎖は読み手が辿る。
- **落としたものがある。** Mathlib 標本の ext 形 94 件のうち **7 件**は
  `to_additive` / `to_dual` が `@[ext]` を代理適用したもので、**何も出していない**。
  拡張が Mathlib のものなので引けない。**間違った親より無言を採った。**
- **IR の増分は +144,936 B / 15,093,293 B = +0.96%**。`attrs` の +0.0054% より 2 桁大きい
  のは `selectionRange` を全宣言に**常に**書くため。省略規則
  (「range と違うときだけ書く」) は**キーの不在に 2 つの意味を持たせる**ので採らない。
- **反証条件は 3 版で数えた**: 生成宣言が由来より前に並ぶ件数は
  v4.31.0 / v4.32.2 / v4.33.0 で **0 / 0 / 0**。**B-0 §6 は書き換えない。**
  ついでに 3 版すべてで extractor が建つことも再確認された。
- **ゲート GATE 9** (`tools/e2e-micro.sh`) は宣言ごとに名前で由来を照合し、
  **比較した本数**・**由来を主張した総数 (9)**・**`sel == range` の 42 件のうち
  名乗っていない 33 件**を数える。最後の数が「全部に色を付ける分類器」を落とす。
  一度落とした実測: `extOriginOf` から `sameRange` の条件を外すと **exit 1** で
  `GATE 9 FAIL  Micro.Gen.Solo.ext: generated is ["ext", "Micro.Gen.Solo"], expected null`。
- **描画は 1 バイトも動かしていない。** 折り畳みと表示は束 C。
- **`e2e/micro` に `Micro/Gen.lean` を足した** (`Micro/Basic.lean` ではない — GATE 6 が
  あのファイルに probe を追記する)。ゲート 8 の `reducible` が 9 → 19 になった
  (structure を 6 つ足したので射影が増えた)。

### C-1 (a) docstring の数式

**根拠**: README の「No」の 1 つ目。doc-gen4 は MathJax をクライアントで走らせている。
Mathlib 依存パッケージの docstring は数式を含む。

- **方式【決定 4】: ビルド時に LaTeX → MathML に変換して HTML に焼く。**
  ~~Rust のクレートは `pulldown-latex` を使う~~ → **`math-core` 0.7.0**
  【決定、ユーザー判断 2026-08-22。実測が調査を覆した】。
  `latex2mathml` は 2020 年で更新が止まっており、`katex` クレートは JS エンジンを
  抱き込むので、どちらも入れない。**`pulldown-latex` を外した理由は依存の数ではなく
  出力の正しさ**: `\text{…}` の中しかエスケープしないので `$a < b$` が
  `<mo><</mo>` になる — Mathlib の 2,123 span のうち **61 件 (2.9%)** が
  不正な markup で出る【実測 2026-08-22 → `benchmarks/results/mathml-2026-08-22.txt` §2】。
  変換成功率は 2 つで 1 span しか違わない (2,114 / 2,113) ので、
  **選択は「依存 18 件」と「正しい markup」の間**だった。
  **代償は依存が 30 → 48 crate に増えたこと。** `deny.toml` の
  「deliberately small」はこの日書き換えた。ライセンスは全て許可済で
  `cargo deny check` は緑だが、**NOTICE が MIT 単独の推移的依存を網羅していない**
  ことが分かり、`docs/provenance.md` §8 に検証項目として起票した。
  - **node を実行時に要求しない** — 「利用者は node を払わない」という既存の決定を保つ
    (node は `build.rs` が vite を回すときだけ、つまり開発者と CI のビルド時だけ)。
  - **閲覧側に JS を足さない** — 生成の速さと閲覧の軽さは別の話で、
    ここで数百 KB を足すと後者を失う。MathML はブラウザが自前で描く。
- **変換に失敗した数式は素のテキストに戻す。壊れた MathML を出さない。**
  失敗件数をビルドログに 1 行出す。
- **必ず実測する**: 対象 422 モジュールで (1) 数式を含む docstring の件数、
  (2) 変換成功率、(3) 生成時間の増分。ログ: `benchmarks/results/mathml-<date>.txt`。
- **テスト**: `crates/litedoc4-md` に変換のユニットテスト。`e2e/micro` に
  インライン `$…$`・ブロック `$$…$$`・壊れた LaTeX の 3 形。
- **ゲート**: 既存のブラウザゲート (`tools/check-site-browser.ts`) に、
  MathML が実際に描画されている (幅を持つ) ことを足す。
  **一度落とす方法**: MathML を素のテキストに差し替えて落ちることを見る。
- **撤退ライン**: 変換クレートが対象の docstring で**落ちる/崩れる**、または主要ブラウザで
  描画が破綻する → **クライアント側 KaTeX に切り替える** (静的アセットなので node は
  要らないまま)。切り替えたら README の「閲覧側に JS を足さない」という主張を消す。
  **引かなかった** — 例外もパニックも 0 件で、失敗は `Result` で返る。
  ブラウザ側は未判定 (browser-gate に足していない → 下の「残り」)。

#### 結果【2026-08-22 完了】

数字は `benchmarks/results/mathml-2026-08-22.txt`。要点だけ:

- **対象には数式がほとんど無い** — 5,079 docstring 中 **3 span**、2 モジュールだけ。
  **この項目の価値は対象では測れない。** 母数は Mathlib の書き方 (91,815 docstring /
  2,123 span / 651 docstring)。**「対象で効く」と書かない。**
- 変換成功 **2,113 / 2,123 (99.53%)**。失敗 10 件は `\colim` / `\dotsc` / `\cr` /
  壊れた LaTeX で、**すべて `$…$` のまま残る** (doc-gen4 と同じ出力)。

  `math spans kept as LaTeX N` 行に**0 でも印字される**。
  フォールバックは有効なページを残すので、**この数字以外に何も動かない**。
- ゲートは `tools/e2e-micro.sh` **GATE 10** (入力は `e2e/micro/Micro/Math.lean`)。
  **一度落とした** — 記録はレポート §6。
- **CSS は corpus が出す要素を数えてから取捨した** (§3)。webfont は入れない。

**残り (C-4 までに)**: ブラウザゲートに「MathML が幅を持つ」検査を足す。
`cargo test` は数式の 6 case で落ちたまま — C-4 の再凍結で解消する
(内訳はレポート §7)。

### C-2 (d) 宣言単位の逆引き

**根拠**: #77, #63。doc-gen4 は「blueprint と David's docs でやれ」と閉じた —

## 9. 版は互換トークンである【決定 2026-08-21、CI が捕まえた】

**`[workspace.package] version` を `0.1.4` → `0.2.0` に上げた。**

### 何が起きたか【実測 2026-08-21、`lake package (self-test)`】

束 B で IR schema を 4 → 5 に上げた (B-1 `sorry` / B-2 `attrs` を `[name, value]` に /
B-3 `selectionRange` と `generated`)。**版は `0.1.4` のまま動かさなかった。**
`v0.1.4` には Release があり、`lakefile.lean` の `resolveLitedoc4` は
**要求された ref ではなくこの木の `Cargo.toml` の版**で Release を引く。結果、
schema 5 の IR を書く extractor に **schema 4 しか読めない v0.1.4 のバイナリ**が渡された:

```
litedoc4: parsing …/site2/ir/modules/Consumer.Basic.json:
  invalid type: sequence, expected a string at line 1 column 946
```

`tools/lake-download-gate.sh` の項目 1・2 が落ち、`LAKE DOWNLOAD GATE: FAILED (2 of 5)`。
**古いバイナリが「`attrs` が文字列から配列になった」ことを名指ししている。**

### この番号を動かすもの【決定】

> **IR schema を変えたら、同じコミットで `[workspace.package] version` を動かす。**

- **schema** とは `extractor/Extract.lean` の `schemaVersion` **とその下の形すべて**。
  整数が動かなくても、フィールドを足せば・`attrs` の形を変えれば schema 変更。
  Release されたバイナリが読み戻すもの (台帳・`.lidx`) も同じ扱い。
- **版は飾りではない。**「Release されたバイナリはこの木の IR を読めるか」に答える
  **互換トークン**で、それを読むのは `lakefile.lean` の段 2/3 と `action.yml` の
  `[ "$REF" = "v$V" ]` の 2 箇所。**判断は 1 箇所に集まっていたが、その 1 箇所が読む数値が
  動かなかった。**
- **Release の無い版が正しい状態**であって、穴ではない。段 3 は資産が無いと言って
  段 4 (PATH) → 段 5 (`cargo build`) に落ちる。未 Release の checkout が受け取るべきものは
  まさにそれ。
- **`README.md` / `lakefile.lean` / `action.yml` / `ci-action.yml` の `v0.1.4` は動かさない** —
  あれは**最新の Release** を指していて、利用者が出会う最終状態。この木の版ではない
  (CLAUDE.md「利用者向けドキュメントは最終状態だけを書く」)。`ci-action.yml` の
  `released` ジョブは `@v0.1.4` の**タグ側の木**を checkout するので、そこでは
  ref と `Cargo.toml` が一致したままで、この変更の影響を受けない。
- **既知の穴 (未実装)**: `release.yml` は tag と `Cargo.toml` の版が**一致することを検査
  していない**。ずれた tag を打つと資産は publish されるが `resolveLitedoc4` が
  引かない版に入るので、Release が黙って無効になる (壊れはしない — `cargo` に落ちる)。

### ゲートを「走らせなかった」と言えるようにした

版を上げると `v0.2.0` の資産は存在せず、項目 1・2 は**ダウンロードを実行できない**。
`ok` を返すのは「走らせていない枝に緑を出すゲート」、`FAILED` を返すのは
「壊れていない機構を壊れたと言う」。どちらも嘘なので**世界を 2 つに分けた**
(`tools/deps-docs-gate.sh` の branch 2 と同じ形):

| 判定 | 条件 | 項目 1・2 |
|---|---|---|
| Release がある | 資産 URL が **200** | 今までどおり: 取得・検証・キャッシュ |
| Release が無い | 資産 URL が **404** | **文書化された落ち方**: 段 3 が資産の不在を告げ、PATH が答え、サイトが書かれ、キャッシュには何も残らない |
| 訊けない | curl が非ゼロ / 200 でも 404 でもない | **exit 2**。オフラインは第 3 の世界ではなく、このゲートの失敗 |

- 判定は**最初に 1 回**。`curl -sSL --head -w '%{http_code}'` で **`-f` は使わない** —
  `-f` を付けると 404 が curl の終了コードに化けて、区別したかった 1 点が消える。
- 項目 2 は**鏡像**にした: Release があれば「2 回目は curl を呼んではいけない」、
  無ければ「項目 1 が何もキャッシュしていないので **curl を呼ばなければならない**」。
  空の curl ログは「失敗したダウンロードがキャッシュ扱いされた」ことを意味する。
- **要約と最終行の両方**が `NOT EXERCISED` と言う
  (`LAKE DOWNLOAD GATE: ok (items 1 and 2 not exercised — …)`)。
  緑の最後の 1 行しか読まない者にも、どちらの世界だったかが伝わる必要がある。
- 項目 3 の書庫は Release があればそれ、無ければその場で作る。`fetchRelease` は
  **展開の前に**ハッシュするので、項目 3 が見ているものは変わらない。

### 実測 (すべて 2026-08-21、Apple M1 / macOS 26.0 / Lean v4.31.0)

| 走らせたもの | 結果 |
|---|---|
| Release の**無い**世界 (`0.2.0`) | `world: NO release carries v0.2.0 … answered 404` → **5 項目すべて緑、exit 0**、最終行に `(items 1 and 2 not exercised — …)` |
| **一度落とす** (項目 1 の PATH から `pathbin` を外し、落ち先を壊す) | **exit 1**、`ITEM 1 FAIL  lake run docs exited 4 with no release to download — a checkout ahead of every release cannot build docs` |
| Release の**ある**世界 (`Cargo.toml` を一時的に `0.1.4` に戻す) | `world: a release carries v0.1.4 … answered 200` → **項目 1・2 が実際にダウンロードして落ちる**、exit 1 |

**3 行目が今回の欠陥の再現**であり、同時に「200 側の枝は選ばれ、実際に走る」ことの証拠。
ログには `downloading …/v0.1.4/litedoc4-aarch64-apple-darwin.tar.gz` /
`961382 bytes, sha256 275f48b8… matches …/checksums.txt` / `(downloaded, v0.1.4)` が並び、
**取得も検証もキャッシュも成功したうえで**、その先で落ちる:

```
litedoc4: parsing …/site1/ir/modules/Consumer.Basic.json:
  unknown field `selectionRange`, expected one of `name`, `kind`, … at line 1 column 916
```

**CI が名指ししたのは `attrs` (B-2)、ここで名指しされたのは `selectionRange` (B-3)** —
同じ非互換で、パーサが**先に当たったフィールド**が違うだけ。B-3 を足したぶん破綻が
前に来ている。**片方を直せば済むという意味には読まない。**

`0.2.0` を名乗る木では 200 側は通らないので、**この枝が CI で走るのは次に tag を打った
とき** (`ci-lake.yml` の `download` ジョブ)。手元で確かめるには上の 3 行目と同じことをする —
`Cargo.toml` の版を一時的に Release のあるものに戻す。

**上流の同型欠陥も潰した (2026-08-21)**: `release.yml` は**タグと
`[workspace.package] version` が一致するか検査していなかった**。`v0.3.0` を
`0.2.0` と書いてある木から打つと、資産は `0.3.0` の下に publish される一方、
`resolveLitedoc4` が訊くのは `v0.2.0` なので、**そのリリースは誰にも引かれない**
(利用者は「この版の資産は無い」と言って `cargo build` に落ちるだけなので、
**何も大きな音を立てずに無効になる**)。これは今回直した欠陥と同じ形の 1 段上流
— 「版番号は互換のトークンだ」という前提が、別の場所でも検査されていなかった。
タグのときに一致しなければ**その場で落ちる**ようにした
(分岐は 3 通り実行して確認: 一致 → 通す / 不一致 → 拒否 / タグでない → 通す)。
