# lean-doc

Mathlib に依存する Lean パッケージが、**自分のモジュールだけを短時間でドキュメント化する**ための基盤。
依存ライブラリは再生成せず、公開済みドキュメントへリンクする。

**現在の状態: 検証段階。**抽出器のプロトタイプと HTML 生成器が `experiments/` にあり、
抽出・HTML 生成・増分ビルドの数字は実測に置き換わった。
残っているのは増分の正しさ (stale ページ) と常駐プロセス。

---

## なぜ作るのか

doc-gen4 (v4.31.0) を計装して、Mathlib 依存プロジェクト 431 モジュールの
ドキュメント生成を実測した。コストの大半は、ドキュメントを作る仕事ではなかった。

| 実測 | |
|---:|---|
| **85.0%** | 抽出フェーズが環境ロードに費やす割合 |
| **0.032%** | 走査した定数のうち実際に処理されたもの (8.9 億件中 28 万件) |
| **34×** | 同じ 432 モジュールを 1 プロセスでまとめて抽出したときの高速化 |
| **0%** | HTML 生成フェーズの増分性 (無変更でも毎回全再生成) |

計測レポート → [`benchmarks/doc-gen4-report.md`](benchmarks/doc-gen4-report.md)

## 仮説

> Lean の意味情報をパッケージ単位でまとめて抽出し、依存ライブラリを外部参照にすれば、
> downstream ライブラリのドキュメント生成時間を依存ライブラリの規模から大きく切り離せる。

## 到達点

**3 行とも実測**になった (以前はここが理論値だった)。
出力範囲の差と、前提が外れうる条件は下と計画に書く。

| | 現行 doc-gen4 | lean-doc | |
|---|---:|---:|---:|
| 自パッケージ 431 モジュールの抽出 + IR 永続化 | 1,076s | **13.7s 実測** | **78×** |
| ゼロからサイト構築 (依存込み) | 9.2 時間 CPU | **14.5s 実測** | **約 2,270×** |
| 1 モジュール変更 | 5.2s ※ | **3.30〜4.39s 実測** | 倍率は書けない ※ |

抽出フェーズ・IR 永続化・IR からの HTML 生成は検証段階 1〜3 と段階 4 で実測済み
([`docs/verification-log.md`](docs/verification-log.md))。
14.5s = 抽出 13.71s + HTML 生成 0.82s (どちらも warm 実測)。
**増分は段階 5 で実測に置き換わり、旧「常駐なら 0.03 秒 = 170×」は否定された** —
実測の最小が 3.30 秒で理論値の 110 倍。律速は環境の取得 (81.8%) で、
本来の仕事は 1.4% しかない。常駐プロセスで消せるのはその 81.8% までで、
全域索引の再構築 0.46 秒は残る。

※ **1 モジュール変更の 2 つの数字は同じ仕事ではないので倍率を書かない。**
現行の 5.2 秒は HTML が更新されない状態 (stale) の値で `lake build` を含み、
lean-doc の 3.30〜4.39 秒は HTML を更新するが `lake build` を含まない。
現行が正しく再生成すると 80 秒台になる。無変更のときは現行 2.33 秒 対 lean-doc 0.080 秒
(これも Lake の replay はビルドグラフ全体を検証しているので同じ仕事ではない)。
lean-doc 側はいずれも page cache が warm な場合。cold では環境ロードが
2.5 秒から 13.6 秒に伸びる (cold 合計 25.76 秒、外挿)。**olean を抽出と並行して
先読みすると環境ロードは 6.9 秒に戻り、cold 合計は 19.11 秒になる (実測 + 外挿)。**
**CI が cold 側かどうかは未検証 (仮定)** —
ローカル (macOS) では「olean を展開した直後でも cold のまま」を実測したが、
Linux ランナーでは測れていない ([`docs/approach.md`](docs/approach.md) §3)。13.7 秒には属性収集・instance 索引などの
出力がまだ入っていない (IR 永続化と署名の位置つきタグは入っている)。
HTML 生成 0.82 秒も**下限**で、doc-gen4 のページのバイトの 63.6% しか byte 再現しておらず、
検索索引・静的資産を作っていない。
**倍率は出力の範囲と一緒に動く** — 段階 4 で位置つきタグを足した時点で 85× → 78× に下がった。

2,270 倍のほとんどは実装の巧拙ではなく、**やらなくてよい仕事をやめたこと**による。
78 倍と 2,270 倍は別の主張なので、混ぜて引用しない
(同じ「432 モジュールのページ生成」だけで比べると **3.8 倍**)。

## 計画

アプローチのレベルで書いてある。API・データ構造・ファイル構成は、
計画中の「検証の順序」で仮説が支持されてから決める。

## リポジトリの構成

```
CLAUDE.md                   プロジェクト規則 (計測対象の固定、計測の誠実性)
docs/approach.md            アプローチ計画
docs/verification-log.md    検証段階の結果。数字の SoT
experiments/                検証段階ごとの実験プログラム (Lean / Deno、使い捨て)
benchmarks/
  doc-gen4-report.md        計測レポート (本文)
  doc-gen4-report.html      同・ブラウザ表示用
  doc-gen4-instrumentation.patch   計測に使った doc-gen4 へのパッチ
  tools/                    計測・集計スクリプト
  results/                  計測の生ログ (JSONL)
```

計測対象は常に同じ Lean プロジェクト (`InformationTheory`、431 モジュール、Mathlib 全体に依存) に固定している。
比較は同一ワークロード上でのみ意味を持つため。機材は Apple M1 / 8 コア / 16 GB、
Lean・Mathlib・doc-gen4 いずれも v4.31.0。
