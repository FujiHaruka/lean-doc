      mathlib4_docs (常に master から生成) に向けた場合、どれだけ死にリンクが出るか。

4. 改名の猶予 【実測 (方針ファイル)】
-------------------------------------
  Mathlib は改名時に @[deprecated (since := "...")] の別名を残し、
  .github/workflows/remove_deprecated_decls.yml が毎月 15 日に走って
  既定で「6 か月より古い」非推奨を削除する (raw_to_date の default: '6 months ago')。
  → 改名による名前消滅は 6 か月の猶予がある。モジュール移動には猶予が無い。

5. mathlib4_docs 側で使える機構 【実測】
----------------------------------------
  - /declarations/declaration-data.bmp が全宣言の name -> docLink 表。
    Range リクエストに応答する。ビルド時にこれを引けば全リンクを事前検査できる。
    代償: 66 MB のダウンロードと、ビルドがネットワークに依存すること。
  - /find/?pattern=<name>#doc がクリック時に名前解決する (find/find.js)。
    モジュール移動には強いが、解決のためにブラウザが同じ 66 MB を読む。
    リンク先として既定にはできない。
  - 版付きの Mathlib ドキュメントは見つかっていない。mathlib4_docs は master のみ。

6. 転送量の訂正 【実測】
------------------------
  declaration-data.bmp は gzip が効く: Accept-Encoding: gzip で 5,659,512 B
  (非圧縮 66,715,005 B の 8.5%)。ビルド時全件検査の実コストは 5.7 MB。

7. mathlib4_docs の通常ページは同じファイルを prefetch する 【実測】
--------------------------------------------------------------------
  /Mathlib/Order/Basic.html の head に
    <link rel="prefetch" href="../.././/declarations/declaration-data.bmp" as="image">
  がある。つまり mathlib4_docs のどのページに着地しても読者はこれを引く。
  /find/ 経由のリンクが追加で課す転送量は無い。

8. doc-gen4 PR #396 (interproject linking) が選んだ形 【実測、差分】
-------------------------------------------------------------------
  5 files +268/-9。宣言リンクは <base>/find/?pattern=<name>#doc、
  モジュールリンクは <base>/Module.html。
  ビルド時の存在検査は無い (差分にネットワークアクセスが無い)。
  → モジュール移動には強く、改名・削除には無力な設計。

9. 版付きドキュメントの不在 【実測】
------------------------------------
  Reservoir の mathlib ページ (/@leanprover-community/mathlib) が張る
  ドキュメントリンクは README 由来の mathlib4_docs (master) のみ。
  /versions ページはあるが版ごとのドキュメントは無い。

10. 死にリンクの着地点 【実測】
------------------------------
  存在しないパスは GitHub Pages が doc-gen4 の 404.html を返す (1,633 B)。
  その 404 ページ自体が相対パスで壊れることは doc-gen4 #92 (2022-11, open)。
