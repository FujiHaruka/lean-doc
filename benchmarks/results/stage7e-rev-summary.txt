## B-1. `jump-src.js` が何をいつ読むか【コードを読んで判明】

  ファイル全文 (10 行) — /Users/haruka/dev/lean-projects/.lake/packages/doc-gen4/static/jump-src.js

    1  document.addEventListener("DOMContentLoaded", () => {
    2    const hash = document.location.hash.substring(1);
    3    const tgt = new URLSearchParams(document.location.search).get("jump");
    4    if (tgt === "src" && hash) {
    5      const target = document.getElementById(hash)
    6        ?.querySelector(".gh_link a")
    7        ?.getAttribute("href");
    8      if (target) window.location.replace(target);
    9    }
    10 })

  * 読むのは **`#<declId>` 要素の下の `.gh_link a` の `href` 属性** (jump-src.js:5-7)。
    `data-*` 属性ではない。`a.href` プロパティでもなく **`getAttribute("href")`** なので、
    **解決済み URL ではなく属性の生文字列**が返る。
  * 読むタイミングは **`DOMContentLoaded` のハンドラ内** (jump-src.js:1)。
    click 時ではない。さらに **`?jump=src` が付いていて hash が非空のときだけ** (jump-src.js:3-4)。
  * 読んだ生文字列をそのまま `window.location.replace()` に渡す (jump-src.js:8)。
  * ページ側のロード形態は `<script type="module" src=".././jump-src.js"></script>` で
    `<head>` 内 (doc-gen4 の生成ページ、および我々の render.ts の出力 — `head` 領域は
    byte 一致なので同一)。module script は既定で defer 相当。
  * **doc-gen4 の static 資産で `.gh_link` / `gh_nav_link` の `href` を実行時に読むのは
    `jump-src.js` だけ**。`static/` 以下 15 ファイルを再帰 grep して、`gh_link` に
    触るのは `jump-src.js:6` と `style.css:790` (見た目だけ) の 2 か所しか無いことを
    確認した (`expand-nav.js:8-9` は `a.href` を読むがナビの相対リンク、
    `search.js:144` / `how-about.js:30` は `href` を**書く**側)。

  → §8 の「`jump-src.js` が実行時に `href` を読む」は**正しい**。ただし
     「実行時」は **DOMContentLoaded 時、かつ `?jump=src` 付きのときだけ**であって、
     ページを開くたびではない。

## B-3. 注入の順序制約【(a) は実測、(b) は未検証】

  (a) **配信時に文字列置換で注入する版 — 順序制約は無い。**【実測】
      置換は HTML がブラウザに届く前に完了しているので、`jump-src.js` が
      いつ `href` を読もうと具体 rev が入っている。裏取りは 2 つ:
      A-1 の byte 一致 (pages-inj == pages-rev、全木) と、B-2 の
      「pages-inj の `getAttribute("href")` が具体 rev」。
      **§8 の「注入が先に走らないといけない」は、この版には当てはまらない。**

  (b) **JS で実行時に注入する版 — 順序制約はある。**【コードからの言明、ブラウザ未検証】
      制約を正確に言うと「注入が先」ではなく:
        **注入が DOM の `.gh_link a[href]` を書き換え終わる時点が、
          `jump-src.js` が jump-src.js:1 で登録した DOMContentLoaded ハンドラの
          実行より前でなければならない。**
      HTML の parse 完了より前である必要は無い (jump-src.js は parse 中には何も読まない)。
      満たし方は仕様上 2 通りあり、どちらも**この段階では実行して確かめていない**:
        - 注入スクリプトを `jump-src.js` より前に置き、同じく DOMContentLoaded で
          登録する (同一イベントのリスナは登録順に発火する)。
        - 注入を同期スクリプトで body 末尾に置く (DOMContentLoaded より前に走る)。
      **ブラウザで確かめていないので「未検証」のまま残す。**
      なお `?jump=src` 付きで開かれたときだけ読まれる (jump-src.js:3-4) ので、
      順序を外したときの壊れ方は「全ページが壊れる」ではなく
      「`?jump=src` のディープリンクだけが壊れる」。
