# stage7c — CommonMark 規則の ablation (実測)

段階 7b の renderer が再現できなかった prose 領域は **47 / 120,261 B**。
段階 7c の block parser がそれを 0 にした。どの規則がどれだけ効いているかは
コードを読んで割り振るのではなく、**規則を 1 つずつ外して採点し直して**測った
(段階 7b が 3 つの抽出追加を ablation で測ったのと同じやり方)。

採点は `experiments/stage4c/coverage.ts` (無改変)。母数 22,028,728 B。
ablation を入れた run のページは**意図的に間違っている** — 読むのは点数だけ。

| 外した規則 | 再現バイト | 落ちる分 | CommonMark 未再現 領域 |
|---|---:|---:|---:|
| (なし = 段階 7c の構成) | 21,919,956 | 0 | 0 領域 / 0 B |
| indented code block (4 桁下げ → `<pre><code>`) | 21,880,244 | 39,712 | 13 領域 / 39,712 B |
| loose list (項目間の空行 → `<li><p>`) | 21,876,134 | 43,822 | 11 領域 / 43,822 B |
| nested list (項目の中の字下げ → `<ul>` 入れ子) | 21,894,840 | 25,116 | 7 領域 / 25,116 B |
| lazy continuation (字下げ不足の行が段落の続き) | 21,870,293 | 49,663 | 23 領域 / 49,663 B |
| 項目境界 (字下げ不足の**リストマーカー**は項目を閉じる) | 21,873,361 | 46,595 | 18 領域 / 46,595 B |
| 順序付きリストが段落を割れるのは `1.` のときだけ | 21,914,293 | 5,663 | 2 領域 / 5,663 B |
| `_` の強調 (md4c の flanking 判定つき) | 21,919,424 | 532 | 1 領域 / 532 B |
| 7 つ全部を外す | 21,772,796 | 147,160 | 52 領域 / 147,160 B |

**合計は 47 にならない。**1 つの領域が 2 つ以上の規則を必要とすることがあるので、
各行は「その規則だけを外したときに壊れる領域」であって分割ではない。

**7 つ全部を外すと 52 領域 / 147,160 B** で、段階 7b の 47 / 120,261 より悪い。
段階 7b の素朴なレンダラと同じものに戻るわけではない (ブロック構造の入れ物は残る)
ので、この行は「7 規則の合計効果」であって「7b との差」ではない。
