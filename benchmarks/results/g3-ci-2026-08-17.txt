**段 C / 段 D はこの 2 run では 1 度も走っていない。** package は run ごとに
決定的に生成されるので、増分ビルドは常に無変更になり、抽出器が起動すらしない
(requests 0)。地図を書く経路に入らないので、取り分は測れない。
**測れたのは「回帰が無い」ことだけ。**

## 2. 1 モジュール変更の段を足した (commit e13897e)。**2 回続けて落ちた**

判定は tools/onemod-gate.sh の 1 本で、e2e と CI が同じものを呼ぶ。
利用者に配る雛形 (.github/workflow-templates/lean-doc-docs.yml) は変えていない。

### run 31963079828 — **段 C を跨ぐアップグレードは 1 回だけ全再描画する**

```
render-all linkIndex: the dependency map moved during this run (5b607769821c6e58 -> c03219d3c5f163be)
impact  mode all -> 13 page(s)
work    extract 1 / render 13 / requests 1
```

キャッシュから復元した地図が段 C 以前の形式 (自パッケージの宣言群を持ち、
`.key` sidecar が無い) だったため、最初の抽出でいまの形に書き直され、
ダイジェストが動き、全ページが再描画された。**一度きりの移行コストで、
利用者も段 C を含む版に上げた後の最初の増分ビルドで同じものを払う。**

→ ゲートは定常状態を問うているので正しい。**直したのはハーネス**:
2 回編集して 2 回目を測り、1 回目のログも残す (commit 611c4f3)。

### run 31963305864 — **CI は段 C/D 以前の `lean-doc` を走らせていた**

2 回目の編集でも地図が動いた。抽出器はその run で新しく建てられている
(`extractor 15.815 built`) のに、serve.out に `omitted` も `reused` も出ない。
**渡す側の Rust が古かった。**

```
ワークフローの Rust キャッシュキー  cargo-<os>-<hashFiles('lean-doc/Cargo.lock')>
                                  → ソースが動いても Cargo.lock は動かない
tools/ci-build.sh                 if [ -x "$LEAN_DOC_BIN" ] で cargo を呼ばなかった
```

→ `cargo` を必ず呼ぶように直した (commit 7859e5c)。新鮮なツリーなら約 0.2 s。
抽出器側も `-nt` でソースが新しければ建て直す。

**leg 3 の CI 数字は影響を受けていない** — `d5af924`〜`4590030` は
`crates/` も `Cargo.lock` も触っていない【確認済】。

**13 ページ → 1 ページ、地図の書き出しは 0.001 s。**

ただしこの package は 13 モジュールなので、**倍率は対象の規模に依存しない主張ではない。**
