新しい Lean で extractor は建つか — v4.32 は建ち、v4.33 は建たない【実測 2026-08-18】
================================================================

未検証項目「Lean のバージョン差」を潰すための 1 本 (→ docs/plans/unverified-sweep.md U5)。
**この項目は 2 つが混ざっていた**:

  後方互換 — 古い Lean に合わせにいくか  → **やらないと決めてある**(決定)
  前方追随 — 新しい Lean で壊れないか    → **未検証。しかも利用者が最初に踏む**

`ci-extractor-portability.yml` の X5 が見ているのは「**違う toolchain 用に建てた
バイナリを使ったとき**」で、「**新しい toolchain でソースから建てたとき**」ではない。
別の壊れ方をする、というのがこの実測。

前提 — どれだけ遅れているか【実測】
------------------------------------
  対象・フィクスチャ・手元の既定 : v4.31.0 (2026-06-15)
  Lean の最新                   : **v4.33.0 (2026-08-10)**、間に v4.32.0/.1/.2
  → **2 マイナー版遅れている。**

機材と条件
----------
  Apple M1 / macOS 26.0。対象は **e2e/micro** (Mathlib 非依存) の複製で、
  `lean-toolchain` だけを書き換えた。**e2e/micro 自体には触っていない**。
  extractor はいずれも `lake env lean --root=<extractor>` + `leanc -rdynamic` で建てた
  (build.sh は使わない — あれは extractor/build/ を上書きするので、対象 1 用の
  バイナリが消える)。

v4.32.2 — 建つ。IR も動かない【実測】
--------------------------------------
  micro の lake build      : ok
  extractor の lean + leanc : ok
  IR                        : **v4.31.0 と byte 一致 (6 モジュール / 差分 0 ファイル)**

  **一度やり直している**: 最初の比較は 43 宣言 対 42 宣言で 1 件違ったが、差の正体は
  `e2eGate6Probe_` — **e2e ゲートが注入する探針**で、Lean の版差ではなく
  フィクスチャの状態差だった。同じ木を v4.31.0 でも建てて取り直したのが上の 0 ファイル。
  **条件を 2 つ変えて 1 つの結論を出しかけた、この日 2 度目。**

v4.33.0 — 建たない。壊れているのは 1 箇所【実測】
--------------------------------------------------
  micro の lake build : ok (フィクスチャ自体は v4.33.0 で通る)
  extractor           : **コンパイルエラー**

      extractor/Extract.lean:812:2: error: Missing cases:
      ReducibilityStatus.instanceReducible

  `getCustomAttrs` の `match ← getReducibilityStatus decl` が、v4.33.0 で増えた
  コンストラクタを網羅していない。**Lean 側が enum に 1 つ足したというだけ**の変化。

  **他にも壊れているかを測った**: 複製に `| _ => pure ()` を当てて (修正ではなく探針)
  建て直すと **error 0 で通った**。つまり **v4.33.0 との差はこの 1 箇所だけ**。

  **落ち方は「大声」で正しい** — 黙って属性を落とした IR を書くのではなく、
  コンパイルが止まる。U5 の合格条件はこちら側だった。

主張の限界
----------
  - **Mathlib 依存パッケージのことは何も言っていない。** 測ったのは Mathlib 非依存の
    micro だけで、Mathlib が v4.32 / v4.33 に対応しているかは Mathlib 側の話
  - **v4.32.0 / v4.32.1 は測っていない** (v4.32.2 のみ)
  - **v4.33.0 の探針は修正ではない。** `_ => pure ()` は新しいコンストラクタを黙って
    捨てるので、そのままでは属性が 1 つ落ちる。ここで測ったのは
    「**障害が 1 箇所であること**」だけで、**その版で IR がどう変わるかは測っていない**
    (探針バイナリでの抽出は、3 つの複製が 1 つの `micro-dep` を共有していたせいで
    `incompatible header` で止まった — **版違いの olean はここでも大声で落ちる**、
    という X5 と同じ答えが 3 度目に出ただけで、IR の比較にはならなかった)
  - 利用者から見た症状は **Lean のコンパイルエラー**で、「litedoc4 が v4.33 に未対応」
    とは書いていない
