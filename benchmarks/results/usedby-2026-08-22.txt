## 2. 設計を決めた数字【実測】

計画は「宣言ごとに `Used by (N)` を HTML に焼く」だった。3 案を測って
**`instances` / `instances-for` と同じ「空マークアップ + app.js が開いた時に埋める」**
に決めた (→ 計画 §4 C-2)。

| | HTML 増 | 別ファイル | 1 モジュール編集で古くなるページ |
|---|---|---|---|
| インライン展開 | **+2.10 MB** | 無し | **最大 15 / 中央値 2** (422 中) |
| 採用: 空 details + 別ファイル | +645 KB | 730 KB | **0** |

- インラインをやめた決め手は**バイト数ではなく機構**。ページの内容がサイト全体の
  事実に依存すると、「A を編集したら A が参照している先のページも古い」という
  **impact の新しい向き**が要る。今の `self` / `referrers` / `importers` の
  どれでもない。
- **同じ問題をこの木は既に 2 回解いている** (`instances_for_html` の doc コメントが
  そのまま当てはまる)。3 つ目の答え方を足さない。
- 代償: **JS 無しでは件数も一覧も見えない。** `Instances For` と同じ性質。

    C-1    warm 中央値 0.4421
    C-2    warm 中央値 0.4656                        +5.3%

**遅くなった。隠さない。** global が +0.015 s (+18%) で、内訳は
(a) `ModuleFacts.refs` を 422 モジュールぶん組み立てる、
(b) state を 838 KB から 1.31 MB 書く、
(c) 730 KB の JSON を作る。render の +0.011 s は 4,584 個の `<details>`。
**壁時計はゲートに使わない** (page cache で 5 倍動く) ので、この数字は
報告のためのもので判定には使っていない。


## 5. ゲート

### `tools/usedby-gate.sh` — 不変量、外部オラクル無し

  A の IR が B を参照する ⟺ B の used-by.json のエントリに A が居る

**両方向を別々に落として確認した**【実測 2026-08-22】。

  1. 前向き (取りこぼし): 1 キー (`Combinatorics.Polymatroid`) を消して回した
       USEDBY GATE FAIL  9 reference(s) the IR has and used-by.json does not: …
       exit 1
  2. 後ろ向き (でっち上げ): 1 キーに存在しない利用者を注入して回した
       USEDBY GATE FAIL  1 entry/entries in used-by.json that no IR reference
                         supports: Nobody.Uses.This -> Combinatorics.Polymatroid
       exit 1

**両方向が同時に落ちたら対象ではなく比較器を疑う** (2026-08-17 に踏んだ形)。
このゲートは片方ずつ落ちることを確認済み。

通常の出力:

  対象     usedby  422 module(s), 4584 declaration(s); 849 target(s) /
                   10163 edge(s) agree in both directions
  micro    usedby   10 module(s),   92 declaration(s);  64 target(s) /
                    151 edge(s) agree in both directions

期待側は **Python の dict of sets** で組み立てている。Rust 側 (`HashMap` +
モジュールごとの `BTreeMap<String, Vec<u32>>`) と設計も言語も別
(CLAUDE.md「オラクルを同じ言語・同じ設計で書き直さない」)。
**辺が 0 件なら落ちる** — 何も比較していない緑を返さないため。

### `benchmarks/tools/check-site-browser.ts` 検査 4b

「マークアップが在る」と「開いたら埋まる」は別の問い。空で出荷するので後者を
見るものが他に無い。

  ok   Used by fills in — 7 of 8 blocks name a user

一度落とした記録【実測 2026-08-22】 — サイトのコピーの `used-by.json` を `{}` に
差し替えて回した:

  FAIL Used by fills in — all 8 blocks answered "None" — the map reached the
       page but says nothing, which is what a wrong key looks like
  BROWSER GATE: 1 failed   (exit 1)

**「空でも None と答えるので緑」にならない**ことがこの落とし方の要点。


## 6. 落ちている凍結フィクスチャ

`cargo test --workspace` は **3 本**落ちる (33 本は緑)。C-4 で再凍結するまで。

  litedoc4-md   tests/docgen4.rs      数式 5 case (C-1)
  litedoc4-md   tests/ts_docstring.rs 数式 1 case (C-1)
  litedoc4-render tests/page_parts.rs 187 case 全部 (C-2) —
      全宣言に `Used by` の <details> が付いたため

**C-2 で新しく落ちたのは 3 本目だけ。** 1・2 本目は C-1 のもの。

なお `crates/litedoc4-global/tests/state_and_delta.rs` の
`the_state_file_is_the_prototypes_bytes` が固定している **861,999 B は
`refs` を足したことで動く**。この機材に 432 モジュールの corpus
(`/private/tmp/lean-doc-relay/w7h/base-ir`) がもう無いので**測り直せていない** —
テストは `#[ignore]` で、fixture が無いと byte 比較に届く前に
「no prototype state at …」で落ちるので、**黙って嘘をつく状態にはなっていない**。
→ 計画 §4 C-2 の残件。
