属性を (name, value) に分けたときの IR の太り方 (B-2)
=====================================================

日付: 2026-08-21
問い: schema 4 の連結文字列 `"deprecated Foo"` を schema 5 の `["deprecated", "Foo"]` に
      変えたとき、IR はどれだけ太るか。計画 §4 B-2 の撤退ラインが
      「IR が太るなら文字列のまま描画側で分割する案に戻る」なので、その判定材料。

機材 / 条件
-----------
- Apple M1 / 16 GB, macOS 26.6.1 (Darwin 25.6.0 arm64)
- 対象パッケージ: /Users/haruka/dev/lean-projects (422 モジュール / 宣言 4,584)
  lean-toolchain leanprover/lean4:v4.31.0
- 抽出器: extractor/build/extract (2026-08-21 ビルド、schema 5)
- 暖機: olean は page cache に載っている (直前に同じ抽出を 1 回回している)

1. 対象での増分 【実測】
------------------------
  modules/*.json 合計            15,093,293 B
  属性の出現                            163 件 (6 種類)
    schema 4 の表現 (連結文字列)      1,533 B
    schema 5 の表現 (2 要素配列)      2,347 B
    差                                 +814 B
  IR 全体に対する増分              +0.0054%

  → **撤退ラインには遠い。** 文字列に戻す判断はしない。

  数え方: 生成済み IR の `attrs` を読み、schema 5 の各要素について
  (a) 実際に書かれている 2 要素配列のバイト数と、(b) 同じ内容を schema 4 の
  連結文字列に戻したときのバイト数を両方数えた。**推定ではなく、同じデータの
  2 通りの表現を数え比べたもの。**

2. e2e/micro での増分 【実測】
------------------------------
  属性の出現 23 件 / schema 4 で 364 B -> schema 5 で 475 B (+111 B、属性バイトの +30.5%)

  比率が対象より大きいのは、このフィクスチャが**値を持つ属性しか置いていない**ため
  (対象の 163 件は 6 種類しかなく、ほぼ全部が裸の名前)。
  **フィクスチャの比率を対象に外挿しない。**

3. 通しで建つこと 【実測、1 回】
--------------------------------
  litedoc4 build --root <target> --lib InformationTheory --jobs 4
    extract 422 / render 422 / requests 1 / ir 853 file(s) (844 module read = 2.00 full pass)
    full in 13.2714 s

  **1 回だけの数字なので速度の主張には使わない。** ここで確かめたのは
  「抽出器が書く schema 5 を Rust 側が読み切って通しでサイトが建つ」ことだけ。

4. 古いバイナリが新しい IR を読むと、黙って誤解釈せずに落ちる 【実測】
----------------------------------------------------------------------
  B-2 以前にビルドした `target/release/litedoc4` で schema 5 の IR を読ませたところ:

    litedoc4: parsing …/InformationTheory.Fano.json:
      invalid type: sequence, expected a string at line 1 column 29351
    exit 1

  **文字列を期待している読み手に配列を渡すと、その場で名前を出して落ちる。**
  静かに空扱いされたり、片方だけ読まれたりはしない。
  (この行が出たのは計測手順の事故 — バイナリを建て直さずに走らせた — だが、
  失敗の仕方が望ましい形であることの実測ではある。)
