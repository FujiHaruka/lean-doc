X1 / X4(macOS) — `extract` は何に依存して決まるか
==================================================

問い (docs/plans/distribution.md §3 D1):
  extractor のプリビルドを配れるか。配れるのは「対象の toolchain だけ」で決まる場合。
  tools/ci-build.sh は「別パッケージで byte 一致」を実測済みだが、**2 つの依存セットが
  互いのコピー**だったと自分で注記している。その穴を塞ぐ。

計測条件【実測 2026-08-18】
  機材        Apple M1 / 16 GB / macOS (Darwin 25.6.0), arm64
  toolchain   leanprover/lean4:v4.31.0 (3 パッケージすべて同一)
  ページキャッシュ  warm (連続実行、1 本目のみ cold 寄り: 19.01s real / 10.10s user)
  手順        extractor/build.sh を TARGET_REPO だけ替えて 3 回。`lake build` は
              一度も走らせていない (Extract.lean は `import Lean` のみで、対象は
              環境を借りるためだけに要る)
  生ログ      /private/tmp/lean-doc-relay/dist/x1.out (作業領域、削除済み)

--------------------------------------------------------------------------
1. 依存セットを 0 個から 15 個まで振っても、バイナリは同一
--------------------------------------------------------------------------

  対象                    依存パッケージ                       ビルド    SHA-256
  e2e/micro               0 個 (Lean core のみ)                19.01 s   226d49ab…
  e2e/micro-dep           path 依存 1 つ                        9.63 s   226d49ab…
  lean-projects           15 個 (Mathlib 全体・aesop・Qq …)    11.69 s   226d49ab…
  (昨日 8/17 02:51 のビルド、別セッション)                        —        226d49ab…

  完全な値: 226d49abb29e0e82c78916429a4ea959fec424d8806542b283e62b0e24fcd7d1
  サイズ:   171,334,112 B (4 つとも同一)

  → 差が生まれる余地は Lean のコンパイル段階に無い (leanc 側でも無い)。

  **日をまたいでも一致する** — 4 本目は昨日別セッションで作られたもの。再現ビルド性がある。

--------------------------------------------------------------------------
2. バイナリは可搬 — Lean ランタイムは静的リンクされている
--------------------------------------------------------------------------

  otool -L:
      /usr/lib/libc++.dylib
      /usr/lib/libSystem.B.dylib
  LC_RPATH:   無し
  埋め込まれた /Users/haruka のパス: **1 件のみ**
      /Users/haruka/.elan/toolchains/leanprover--lean4---v4.31.0/include/lean/lean.h
      (leanc に渡したヘッダのパス。実行時には参照されない)

  → libleanshared への動的リンクが無い。171 MB はデバッグシンボルではなく
    静的リンクされた Lean ランタイムの実体 (strip -S で 8 バイトしか減らない【実測】)。
    macOS では OS 標準ライブラリ 2 つだけあれば起動できる。

--------------------------------------------------------------------------
3. 主張の強さの限界 — ここから先はまだ測っていない
--------------------------------------------------------------------------

  * **1 機材・1 OS (macOS arm64)・1 toolchain (v4.31.0)**。
    Linux は leanc の既定が違う可能性があり、そこで静的リンクとは限らない → X3 / X4
  * **「起動できる」と「正しい IR を書く」は別**。ここで比べたのはバイナリの byte であって
    出力ではない。ただし byte が同一である以上、同じ入力に同じ出力を返す
  * **別 toolchain の環境で走らせたときの壊れ方は未検証** → X5。
    静かに壊れるなら、プリビルドを配る前に版検査が要る
  * 実行時に olean を読むので `LEAN_PATH` が要る。これは `lake env` が対象側で作るもので、
    バイナリには埋まっていない (埋まっていたら可搬ではなかった)
