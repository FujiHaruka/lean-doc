## D. 素朴照合 — IR の平文 + `refs` 集合だけでリンクを再構成した上限

アルゴリズム: `binders + type` を識別子形トークンに切る → トークンが `refs` の完全名ならその定数へ link、そうでなくて短縮名が `refs` 中で一意ならその定数へ link、それ以外は素通し。IR が持っているデータだけを使う中でいちばん強い素朴解法。

> **この評価は位置を問わない。** 宣言ごとに (テキスト, 対象) の**多重集合**を比較していて、アンカーがページのどこに出るかも、隣接テキストも見ていない。したがってここの数字は**位置を無視した上限**であり、実際に再現できる率ではない (実際の描画はさらに難しい)。

| | |
|---|---:|
| 突合した宣言 | 3,477 |
| doc-gen4 が出したリンク (正解) | 72,421 |
| 素朴照合が出したリンク | 37,462 |
| 一致 | 37,458 |
| 取りこぼし | 34,963 |
| 余計に出した | 4 |
| **recall** | **37,458/72,421 = 51.7%** |
| precision | 37,458/37,462 = 100.0% |
| **宣言単位の完全一致** | **140/3,477 = 4.0%** |
| … うちリンク 0 個の自明例 | 4 |

到達可能な上限: 素朴照合が出せるのは「テキスト == 完全名」か「テキスト == 完全名の接尾辞」のアンカーだけなので、天井は **40,556/72,421 = 56.0%**。(参考: テキストが単に識別子の形をしているアンカーは 43,462 = 60.0% あるが、うち 2,906 件は `MeasureTheory.volume` → `MeasureTheory.MeasureSpace.volume` のように対象名の接尾辞にすらなっていない。)

precision 100.0% は「出したものはほぼ当たる」であって「足りている」ではない。**recall が上限で半分**というのがこの節の結論。

## F. あて先解決 — こちらは集合で足りている

B〜E は「どこにリンクを張るか」の話。**張る先の名前を解決できるか**は別問題で、そちらは IR がほぼ完全に持っている、という対照。

348 ページの内部アンカー **80,743 件 / 2,442 種**を、IR から作れる名前集合 (宣言名 4,750 + `refs` 1,446 + `members` 194 + `deps/*.json` 533、和集合 **5,300 エントリ**) に当てる。

| 領域 | アンカー | 種 | 解決できない | 種 |
|---|---:|---:|---:|---:|
| `div.decl_header` | 72,421 | 1,062 | 0 | 0 |
| `ul.equations` | 3,278 | 736 | 0 | 0 |
| その他 (docstring・instances・structure field) | 5,044 | 1,989 | 293 | 188 |
| **合計** | **80,743** | **2,442** | **293** | **188** |

取りこぼしは **293 件 / 188 種 = 0.36%** で、その **293 件全部が docstring の `<code>` 内 autolink**。署名 (`decl_header`) と equations の取りこぼしは 0。docstring の autolink は本文中の名前を環境全体から引くもので、その宣言の `refs` には現れない — IR の欠落ではなく、別の索引が要るという話。

数え方: `href` が最初の属性であるアンカーだけを数えている (93,322 件)。`class` が先に来るのは `a.break_within` (宣言自身の名前リンク。`nav.internal_nav` の宣言ジャンプ表にも同じものが出る) と `a.hover-link` (見出しのアンカー) だけで、合わせて 8,771 件 — いずれも自己リンクなので相互参照の数からは外してある。同ページ内アンカー (348 件、すべて `#top`)、外部リンク (3,825 件)、フラグメント無しのモジュールリンク (8,406 件) も除外。

## G. その他の差分 (IR に足りないもの / 規則で埋まるもの)

### 宣言の並び順

IR の `line`,`col` で並べ替えると HTML の並びを **348/348 ページ**で再現する (安定ソート = 入力順を保存)。ただしキーが同値になるページがあり、`(line, col)` だけで順序が**一意に決まる**のは **346/348 ページ**。

タイのあるページ 2 / 宣言 4:

* `InformationTheory.Polymatroid.Basic`: `Combinatorics.Polymatroid.ext`, `Combinatorics.Polymatroid.ext_iff`
* `InformationTheory.Shannon.EntropyPower.Ext`: `InformationTheory.Shannon.differentialEntropyExt_def`, `InformationTheory.Shannon.differentialEntropyExt`

→ IR に宣言の**出現順**そのもの (または declaration range の終端) を入れないと、この 4 件はコイントスになる。

### Equations

doc-gen4 は `equationLimit = 200` の規則で、描画テキスト長がこの値以上の equation を落とし、落としたときだけ `One or more equations did not get rendered due to their size.` の li を先頭に足す (`DocGen4/Process/Base.lean`, `DocGen4/Output/Definition.lean`)。IR の `equations` 文字列にこの規則を当てると:

| | |
|---|---:|
| 省略の通知が出るページ側宣言を当てた | 195/195 |
| 通知が出ない宣言を当てた | 3,282/3,282 |
| `ul.equations` の有無を当てた | 653/653 |
| `li.equation` の個数まで一致 | 3,477/3,477 |

→ ここは IR に追加フィールドは要らない。**規則を消費側に写せば済む**。

### `render := false` 相当 — IR にあって HTML に無い宣言

HTML ページのある 348 モジュールの IR 宣言 3,663 に対し HTML の `div.decl` は 3,477。差 **186** の `kind` 内訳:

| IR の `kind` | 件数 |
|---|---:|
| `theorem` | 109 |
| `definition` | 41 |
| `constructor` | 36 |

例: `Combinatorics.Polymatroid.mk`, `Combinatorics.Polymatroid.rank`, `Combinatorics.Polymatroid.rank_empty`, `Combinatorics.Polymatroid.rank_mono`, `Combinatorics.Polymatroid.rank_submodular`, `InformationTheory.FiniteJointPMF.mass`

**この 186 件は、IR 側で親 `structure` の `members` に載っている名前と完全に一致する** (186/186)。逆向きも成立していて、`members` に載る名前が単独の `div.decl` として出ることは 0 件。つまり doc-gen4 が親の `structure` に畳む集合は、**IR が既に持っている情報だけで正確に決まる** — 追加フィールドは要らない。

### `gh_link` の終了行

`gh_link` は 3,477 件、全部が `#L<開始>-L<終了>` の範囲リンク。開始行は IR の `line` と 3,477/3,477 一致するが、**終了行に相当するフィールドが IR に無い** → 3,477 リンク全部が再現不能。declaration range の終端を IR に足す必要がある。
