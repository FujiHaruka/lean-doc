## 0. HTTP Range は GitHub Pages では使えない

### 素の Range (Accept-Encoding: identity) — 成立する
  HTTP/2 206 
  content-range: bytes 1000-1099/405402
  content-length: 100

### ブラウザと同じ Accept-Encoding では、Range が gzip 後のバイト列に掛かる
  HTTP/2 206 
  content-encoding: gzip
  content-range: bytes 1000-1099/49193
  curl: (56) Error while processing content unencoding: incorrect header check
  → content-range の分母 49193 は gzip 後の長さ。返るのは gzip ストリームの断片で、
    curl は 'incorrect header check' で復号に失敗する。

### バイナリの content-type でも同じ (image/bmp も gzip される)
  HTTP/2 206 
  content-encoding: gzip
  content-range: bytes 0-63/5655790
  先頭 16 バイト: 00000000: 1f8b 0800 0000 0000 0003 ccbd cb8e 2439  ..............$9
  → 1f 8b 08 は gzip のマジック。66,418,003 B のファイルに対し分母は 5,655,790 B。

  fetch() は Accept-Encoding を設定できない (forbidden header name) ので、
  ブラウザから identity を要求する手段が無い。→ Range 方式は却下。
