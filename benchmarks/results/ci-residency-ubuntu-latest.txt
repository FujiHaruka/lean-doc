## what this does not say

1. **It does not measure `importModules`.** Residency is a proxy. The macOS
   number came with an import time; this one does not, because building the
   extractor in CI was deliberately out of scope.
2. **It does not say *which* 62.4%.** A cold import reads ~2.59 GB (macOS,
   measured). If the resident set covers that hot set, the import is nearly
   warm; if residency is spread evenly, ~37% of what the import needs still
   faults. mincore cannot distinguish these without the extractor's read set.
3. **n=1**, one runner size, one image.
4. **62.4% may be capacity-limited rather than characteristic.** 5.19 GiB of
   oleans on a 7.75 GiB runner that already had 2.3 GiB cached: the cache
   ended at 6.20 GiB of 7.75 GiB total. A larger runner may do better, which
   makes the runner size a variable rather than a constant.
