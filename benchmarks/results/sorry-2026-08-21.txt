2. なぜ安いのか — `collectAxioms` は推移閉包を歩かない 【実測 + Lean のソース】
--------------------------------------------------------------------------------
  計画は「`collectAxioms` は推移閉包なので 4,584 宣言ぶん繰り返すと莫大」と
  読んでいた。**それは Lean の実装と違う。**

  `Lean/Util/CollectAxioms.lean` は `PersistentEnvExtension`
  (`exportedAxiomsExt`) を持っていて、**宣言ごとの公理配列は olean を書くときに
  計算されて焼かれている**。`collectAxioms` はまず `extFind?` を引き、
  **import された定数ならその配列への binary search で答えて式を 1 つも歩かない**。
  この抽出器が見る宣言は全部 import 側 (`importModules` で対象の olean を読む) なので、
  **共有すべきメモは olean を建てた者が既に 1 回払っている**。

  v4.31.0 / v4.32.2 / v4.33.0 の `CollectAxioms.lean` は該当箇所が同一
  (`public def collectAxioms` の本体が 3 版とも同じ 5 行)【実測、
  ~/.elan/toolchains/*/src/lean/Lean/Util/CollectAxioms.lean】。
  **版に依存した偶然ではない。**

3. 天井 — 全宣言が汚染されていたら 【実測、warm】
--------------------------------------------------
  §1 が測ったのは安い側だけなので、高い側を別に測る。

  高い側は **`"direct"` の判定**、つまり宣言自身の型と値を `Expr.foldConsts` で
  歩く `mentionsSorryAx`。製品版はこれを**答えが `"direct"` になり得るときしか
  呼ばない** (公理配列に `sorryAx` が無ければ 2 値のどちらでもない)。
  天井は「早期脱出を外して全宣言で呼ぶ」ことで測れる:

  - 計測用の使い捨てバイナリ (scratchpad、**コミットしていない**)。
    `sorryTag` から早期脱出を外し、`mentionsSorryAx` を全宣言で走らせる。
    `throwError` を 1 本入れて `Bool` を強制した — **使われない `let` は
    コンパイラがクロックの向こうに沈める**ことが本当にある (writeIRTree の
    `bytes == 0` の注記と同じ罠)。
  - **答えは変わらない**: この天井バイナリが書いた IR は製品バイナリの IR と
    **木ごとバイト一致**【実測、`diff -r` exit 0】。同じ答えを高い方法で出している。

    回   sorry(s)
     1    0.996    <- cold (証明項のページに初めて触る)
     2    0.594
     3    0.594

  **0.594 s = ablation 側 `total` 5.916 s の 10.0%。** つまり:

  - **撤退ライン +10% は、まさにこの早期脱出が救っている線。**
    全宣言が `sorryAx` を踏んでいるパッケージなら、この機能は撤退ラインちょうどを
    払う。0.10% と 10.0% の間は**汚染された宣言の割合で線形に決まる** 【外挿。
    実測したのは 0% (§1) と 100% (§3) の 2 点だけ】。
  - **B-1 の利用者層 (形式化途中のパッケージ) は 0% ではない。** それでも
    100% になることはまず無く、10% 汚染で ~1% が期待値【外挿、同じ 2 点から】。

4. 出た答え 【実測】
--------------------
  対象 422 モジュール / 4,584 宣言:

    sorry   0.006s  (4584 asked, 0 direct, 0 transitive)

  **0 件は「測れていない」ではないことを別経路で確かめた。** 対象の
  `InformationTheory/**/*.lean` を `\bsorry\b` で引くと 24 ファイルが当たるが、
  **全部が散文** (「0 sorry / 0 residual」「no `sorry`」「sorryAx-free」など、
  パッケージ自身が sorry 無しを宣言している docstring)。項としての `sorry` は無い。
  **抽出器の答えと本文の突き合わせが一致する。**

  バイト一致**し、`index.json` の差は `ablations` キー 1 つだけ【実測】。
  **だから §1 の比較は綺麗だが、それは同時に §1 が安い側しか測っていない証拠でもある。**

6. 読み方
---------
- **「+10% を超えなかった」を「この機能はタダ」と読まない。** タダなのは
  汚染 0% の対象での話で、天井は撤退ラインちょうど (§3)。
- **`sorry` phase タイマー (0.006 s) を使うこと。** 腕どうしの `total` の差は
  ノイズ床の下で、符号すら安定しない (対 4 は off の方が遅い)。
- **`--no-sorry` の IR を描画に使わない。** `ablations` が付き、描画側が拒否する。
  拒否は正しい: 汚染された宣言がある対象では、この IR は「穴が無い」と嘘をつく。
