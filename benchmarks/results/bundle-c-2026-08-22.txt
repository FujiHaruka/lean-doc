### 差分レビュー (全件)

`docgen4-expected.json` の 5 件、すべて **C-1** (数式 → MathML):

    curated: inline math                  <p>$x^2$</p>
                                       -> <p><math><msup><mi>x</mi><mn>2</mn></msup></math></p>
    curated: display math                 <p>$$\sum_i x_i$$</p>
                                       -> <p><math display="block"><munder>…
    curated: math with markdown inside    <p>$a_*b*_c$</p>
                                       -> <p><math><msub><mi>a</mi><mo>∗</mo></msub>…
    html: escapes in math                 <p>$a &lt; b$</p><p>$$a &amp; b$$</p>
                                       -> <p><math><mi>a</mi><mo>&lt;</mo><mi>b</mi></math></p>
                                          <p>$$a &amp; b$$</p>
    html: table, markup in cells          表のセル内の $e$ が <math> になった

**4 件目は片方だけ変わっている**のが読みどころ: `$a < b$` は MathML になり、
`$$a & b$$` は**ならずに残った**。環境の外の `&` は math-core が受け付けないので、
これは C-1 のフォールバックが実際に効いている 1 件。

`docgen4-expected.json` の他の 322 件、および `cases` 以外のすべてのキーは不変
(スクリプトで全件突き合わせて確認)。

`page-parts-expected.json` は 187 件全部。**理由は 2 つ重なっている**:

- **C-2**: 全宣言の末尾に `Used by` の空 `<details>` が付いた
- **元々 byte 比較ではなかった**: 凍結値はプロトタイプの markup (`div.decl` +
  `div.gh_link`) で、こちらは `section.decl[data-kind]` + header 内の source link
  (M8-b)。テストは `Content` (id / href / stub / 語) に落として比べていた

そこで**比較を byte 比較に強化した**。`Content` は 2 つの異なる markup の間を
橋渡しするためのもので、同じものの間では情報を落とすだけ。`Content` は
「標本が縮んでいないか」を数えるためだけに残した。
`header` は**プロトタイプのまま**で、`Content::matches_head` による比較も M8-b の
宣言済み差分もそのまま。`the_sample_reaches_every_shape` の 19 個のプローブは
プロトタイプのクラス名からこちらのクラス名へ**翻訳**した (形は同じもの)。
**1 個だけ消した** — 「改行で終わる属性ブロック」はプロトタイプ唯一の
非 flatten 要素を指していて、こちらは全部 flatten するので探すものが無い。

### `MIN_SCHEMA_VERSION` 4 → 5【C-4 手順 4、ユーザー判断】

床を上げると 2 つのフィクスチャに**入力として**埋まった schema 4 の IR が弾かれ、
7 本のテストが落ちた (`litedoc4-global tests/global.rs` 4 本、
`litedoc4-render tests/pages.rs` 3 本)。**一度きりの機械的移行**で通した:

    埋め込み IR の `\"schemaVersion\":4` を `\"schemaVersion\":5` に文字列置換
      crates/litedoc4-global/tests/data/global-expected.json   30 ファイル
      crates/litedoc4-render/tests/data/pages-expected.json     32 ファイル
      合計 62

**再直列化ではなく文字列置換**にしたのは、外側の JSON を 1 バイトも動かさないため
(動かすと bless の round-trip 保証が失われる)。移行スクリプトは
(a) 置換前後で長さが変わらないこと、(b) トークンを取り除いた両者が一致すること、
(c) 置換後も JSON として読めること、を検査した。

床を上げて何が変わるか: **古い `litedoc4` が残した IR ツリーが名前で拒否される** —
新しいキーが無いまま半分の内容が欠けたサイトを描くのではなく。実際には
`extract_key` が `irSchemaVersion` を含むので `build` 経路では全再抽出になり、
この床に当たるのは `render` / `site` を古い IR に直接向けたときだけ。
