### 残った members 2 領域は「メンバのデータ」ではない

到達目標は 97.136% (= 96.506 + 0.613 + 0.017) だった。届いたのは **97.099%**、
差は **8,127 B = 0.037 pt**。その 8,127 B は **members 領域に残った 2 件**で、
中身は **field docstring の中の autolink**:

| module | 宣言 | バイト | `<a>` 数 生成側/doc-gen4 |
|---|---|---:|---|
| InformationTheory.Shannon.LZ78.ZivEntropyBridge | `…IsLZ78PerPathParsingFactorization` | 4,763 | 24/25 |
| InformationTheory.Shannon.EPI.L3Integration | `…IsDeBruijnTailHyp` | 3,364 | 13/16 |

両側から `<a …>` を剥がすと **どちらも byte 一致する** — prose 領域に coverage.ts が
当てているのと同じ判定。つまりこの 8,127 B の原因は autolink 索引 (合計 401,987 B の
一部が members 領域に落ちているだけ) で、メンバのデータ欠落は **0 B**。
目標値 97.136% は、members 領域に入り込んだ autolink 分を二重に数えていた。

ログ: `stage7b-member-check.txt` §B。

### instance 索引: 再現率は動かない (動いたら何かがおかしい)

instance 索引はモジュールページに**1 バイトも出ない** — ブラウザが
`declarations/declaration-data.bmp` から埋めるため (`approach.md` §5.5 L3-3)。
実際、上の表で instance 索引に帰する差は **0 B**。これは失敗ではなく仕様どおり。

出ないものを「書いた」で済ませないために、doc-gen4 が書いた索引そのものと突き合わせた。
doc-gen4 は schema 4 が持つ 2 列から `instances[className] ∋ name` と
`instancesFor[typeName] ∋ name` を作る (`Output/ToJson.lean:88-97`) ので、直接比較できる:

## 7. この対象で**通っていない**経路 (未検証と明記する)

`getAllAttributes` の 4 系統のうち、この対象が実際に踏むのは 2 つだけ:

| 系統 | この対象での出現 | 状態 |
|---|---|---|
| customs (`simp` / reducibility) | 89 領域中のほぼ全部 (simp 69, reducible 69, implicit_reducible 4, irreducible 2 — IR 全体) | **採点で一致** |
| enums (`Compiler.inlineAttrs`) | `@[reducible, inline]` 13 領域 (IR 全体で inline 22) | **採点で一致** |
| parametric (extern / implemented_by / export / specialize / deprecated) | 1 件だけ (`@[deprecated … (since := "…")]`)。ただしそのモジュールは doc-gen4 が**ページを出していない** 84 個の側 | **未採点** |
| tags (unbox / never_extract / elab_without_expected_type / match_pattern) | 0 件 | **未検証** |

`Compiler.specializeAttr` は Lean v4.31.0 では `ParametricAttribute (Array Nat)` で、
doc-gen4 が持っている `ToString SpecializeAttributeKind` は**その属性の型ではない**
(doc-gen4 側の死んだコード)。こちらは core の `ToString (Array α)` に合わせてある —
どちらが正しいかはこの対象では判定できない (出現 0)。
