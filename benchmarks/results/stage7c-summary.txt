## 2. autolink 索引 — §8「依存パッケージの写像をどう配布するか」に直結する 3 数字

doc-gen4 の `nameToLink?` は環境全体 (`name2ModIdx`) を引く。IR にはそれが無く、
`deps/` は署名が参照した名前だけ (115,749 B)。足したのは
**依存クロージャ全体の「名前 → モジュール」索引**で、ローカルの doc-gen4 出力
`declarations/declaration-data.bmp` (37,481,374 B) から導いた。

**前提 (未検証)**: これは「上流パッケージの公開ドキュメントサイトから同じファイルが
手に入る」ことを前提にした実装である。**手に入るか / バージョン対応が取れるかは
未検証** (approach.md §8)。ローカル出力から作っているのは計測のためであって、
**配布方式を決めたわけではない。**

| docLink が解釈できず落とした宣言 | 0 |
| **(a) 実サイズ — `.lidx` (グループ化テキスト)** | **8,508,273 B** (gzip **1,332,647 B**) |

### アンカーの前後 (診断。オラクルは coverage.ts)

doc-gen4 が出した 348 ページ上の宣言アンカーを多重集合で突き合わせた:

| | 7b renderer | 7c renderer |
|---|---:|---:|
| doc-gen4 が出していてこちらが出していない | **297** (相異なる宛先 191) | **0** |
| こちらが出していて doc-gen4 が出していない (過剰) | 4 | **0** |

出せていなかった 191 の宛先は **191 / 191 が `declaration-data.bmp` にあった**。
索引以外に 2 つ必要だったものがある:

* **`isNameLit` が `'` `!` `?` を落としていた** — Lean の `isIdRest` はこの 3 つを
  含むので、`Foo.bar'` 型の名前が名前リテラルとして拒否されていた (9 アンカー)。

* **モジュール内フォールバックの探索順** — `nameToLink?` は

### 過剰リンクは増えていない

索引は 258,760 件 = `known` の約 50 倍だが、**過剰アンカーは 4 → 0**。
索引を `known` とは**別の Map** に置き、`nameToLink` が `known` → 索引の順に引くので、
既に解決していたものは解決先が変わらない。署名側 (`Renderer.constLink`) は索引を
一切引かない: `--out` の JSONL (宣言ごとの `decl_header`) が **stage7b と byte 一致**
(23,353,796 B / 4,560 行、`stage7c-header-identity.txt`)。

## 3. CommonMark — 7 規則、ablation で測った

`Output/DocString.lean:393` のフラグは
`MD_DIALECT_GITHUB ||| MD_FLAG_LATEXMATHSPANS ||| MD_FLAG_NOHTML`。
**外部依存は足していない** (このリポジトリに TS の依存管理機構は無く、
`docs/plans/three-axes.md` 事前決定 5 がネットワークを禁じている。npm/jsr の
CommonMark 実装はどれも md4c と byte 一致しない)。

どの規則がどれだけ効いたかは、**規則を 1 つずつ外して採点し直して**測った:

| 外した規則 | 落ちるバイト | 壊れる領域 |
|---|---:|---:|
| lazy continuation (字下げ不足の行が段落の続き) | 49,663 | 23 |
| 項目境界 (字下げ不足の**リストマーカー**は項目を閉じる) | 46,595 | 18 |
| loose list (項目間の空行 → `<li><p>`) | 43,822 | 11 |
| indented code block (4 桁下げ → `<pre><code>`) | 39,712 | 13 |
| nested list (項目の中の字下げ → `<ul>` 入れ子) | 25,116 | 7 |
| 順序付きリストが段落を割れるのは `1.` のときだけ | 5,663 | 2 |
| `_` の強調 (md4c の flanking 判定つき) | 532 | 1 |
| 7 つ全部 | 147,160 | 52 |

**合計は 47 にならない** — 1 領域が 2 つ以上の規則を要求するので、各行は分割ではなく
「その規則だけを外したときに壊れる領域」。7 つ全部を外した 52 / 147,160 が 7b の
47 / 120,261 より悪いのは、ブロック構造の入れ物は残っていて 7b の素朴なレンダラに
戻るわけではないため。**この行は「7 規則の合計効果」であって「7b との差」ではない。**

ログ: `stage7c-commonmark-ablation.txt`、閉じる前の 47 領域は
`stage7c-md-diff-before.txt` (markdown 原文つき)。

**この対象が使っていない構文は実装していない** — doc-gen4 の 348 ページに
`<table>` / `<del>` / `<br>` / task list checkbox は **0 個** (実測)。
参照リンク・画像・permissive autolink も同様。使う対象が来たら
`coverage.ts` がその領域を落とすので、黙って近似することにはならない。

## 7. まだ言えないこと

* **索引の配布方式は決まっていない** (§8)。上流の公開サイトから同じファイルが
  取れるかは未検証で、取れないなら生成側で作ることになる。ここで測ったのは
  「ローカルの doc-gen4 出力から作った場合の 3 数字」だけ。
* **索引は doc-gen4 の出力の写しなので、doc-gen4 がリンクして索引に無い名前は
  出せない。** この対象では 0 件だったが、`name2ModIdx` は環境の全定数を持つのに
  `declaration-data.bmp` は**ページに出る宣言だけ**なので、一般には差がありうる
  (§5.3 が「dead link 実測 3 本」と書いているのがその向き)。
* **CommonMark は md4c の部分集合**。tables / strikethrough / task list /
  hard break / 参照リンク / 画像 / permissive autolink は無い。
  この対象が 1 つも使っていないことは確認済み (実測) だが、**別の対象では落ちる**。
* **2 ページの並び順の差は残っている** (上記 §1)。`coverage.ts` の対応付けが
  位置ではなく名前なので再現率には出ない。直すには doc-gen4 の `qsort` が
  同着をどう並べるかを決める必要がある (§8 の「所有モジュール」とは別問題)。

## 8. 再現手順

```sh
W=/private/tmp/lean-doc-relay/w7c
IR=<段階 7b の schema-4 IR>      # 抽出器は 7b から変えていない
URL=https://github.com/FujiHaruka/information-theory/blob/573793b243fb1343636088eb62d1789ab2b14cec

# (1) autolink 索引を作る
deno run --allow-read --allow-write --allow-env experiments/stage7c/build-link-index.ts \
  --out $W/linkindex --repeat 6 --report <OUT>

# (2) 生成 — 採点用は必ず具体的な rev を埋めた --source-url で描く
deno run --allow-read --allow-write --allow-env experiments/stage7c/render.ts \
  --ir $IR --pages $W/pages --source-url "$URL" \
  --link-index $W/linkindex/link-index.lidx --stats <OUT>
```
