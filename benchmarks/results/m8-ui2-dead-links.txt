Ambiguity: none on this corpus, and not for lack of exposure
------------------------------------------------------------
The rule refuses to link when a path is a component-suffix of **two or more**
known modules. No source path of this package reached that case 【実測: 0 of
193】, so every one of the 192 links above is a unique answer.

That is a property of this corpus and not of the rule. Of the 18,712 distinct
component-suffixes of two or more components in this run's 6,021 known modules,
**479 (2.6%) belong to more than one module** — `Action/Basic.lean` names five.
A rule that took the first match would have been a coin flip on those, and a
wrong page is worse than a missing one: the reader who follows a 404 knows
something is missing.

The dependency map was intact for both runs
-------------------------------------------
Minutes after this measurement the target repository's `lake-manifest.json` was
rewritten by other work in progress there (15 packages -> 9), which would move
every blob URL and therefore this whole table. Both trees above were written
before that: the cross-check is that site-before emits **101,323** github hrefs,
which is the number M7-c recorded on the same target (m7c-site-links.txt), and
site-after emits exactly six more. A run with the shrunken manifest would have
resolved fewer roots and turned dependency links back into relative ones.

`##name` searches
-----------------
`extendLink` sends an unresolved `##name` to the search page, so a name search
whose path resolves to nothing now writes `find/?pattern=…` instead of a link.
No docstring of this package does that 【実測: 0 occurrences of `find/?pattern=`
in either tree】.
